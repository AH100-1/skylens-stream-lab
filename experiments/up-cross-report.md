# 위 방향 교차 검사: 자기 위 방향 갈래 시험과 실행 보고 (F-440)

## 결론
- 묶음 안 방위가 둘 이상인 지그재그 왕복 배치에서는 `up_own` 이 모든 묶음에서 `Some` 이고, 어긋남은 `up_own` 과 `up_rest` 의 각과 1e-9° 안에서 같다. 한 기체에만 구름 2° 를 넣으면 그 묶음의 어긋남이 시드 20개 모두 1.17~1.27° 로 0.3° 문턱을 넘고, 구름이 없으면 최대 0.073° 로 0.1° 미만이다. 이전 시험은 `up_own` 이 늘 `None` 인 배치라 x 축 기울기 평균 갈래만 돌았다.
- 실행(`run`)이 정렬 단계 끝에서 카메라 폴더 라벨(사진 번호 % 3)로 구역마다 교차 검사를 부르고, report.json 의 `up_cross_check` 와 알림에 최대 어긋남을 남긴다. 포즈는 바꾸지 않는다.
- 합성 기본 장면(README 첫 명령 설정, 120장 단구역)에서 최대 어긋남은 0.089°(문턱 0.3° 의 30%), 경고 없음.

## 수치
| 시험 | 배치 | 값 |
|---|---|---|
| 지그재그 왕복, 구름 없음 | 묶음 3개, 방위 ±35° 번갈아, 시드 20 | 최대 어긋남 0.073° |
| 지그재그 왕복, 구름 +2°/-2° (라벨 0) | 같음 | 라벨 0 어긋남 1.174~1.265°, 나머지 묶음 최대 0.849° |
| 구름 부호 바꿈 | +2° 대 -2° | 같은 시드에서 어긋남 차 최대 0.090° |
| 구름 없는 묶음의 자기 위 방향 | 참값 대비 | < 0.1° |
| 합성 기본 장면 run | stride 2, span 48, 120장 | 묶음별 0.0795 / 0.0758 / 0.0886°, 최대 0.0886°, 초과 아님 |
| 합성 작은 구역 run (위치 26곳, span 8) | 구역 3개 | 구역 1·2 에서 7.6~27.5°, 구역 0 은 카메라 하나가 없어 검사 불가 |

나머지 묶음(구름 없는 기체)도 어긋나 보이는 것은 `up_rest` 에 구름 낀 묶음이 섞이기 때문이다. 시험은 구름 낀 묶음의 어긋남이 시드마다 가장 큼을 단언한다.

## 방법
- 시험 배치: 드론마다 방위 -3°·125°·-116° 에 구간마다 ±35° 를 번갈아 더하고 아래로 60° 기울인다. 정확히 180° 반대 방위는 카메라 x 축이 한 직선이라 위 방향이 정해지지 않아(`None`) 옆바람 보정 각을 둔 지그재그를 썼다. 카메라당 0.1° 잡음, GPS 시험 띠와 같은 시드.
- 단언: `up_own`·`up_rest` 가 모두 `Some`; 어긋남 == 두 위 방향의 각; 구름 없음 < 0.1°; 구름 2° 에서 최소 어긋남 > 0.3°; 구름 부호 대칭(차 < 0.15°); 구름 없는 묶음의 자기 위 방향 오차 < 0.1°, 구름 낀 묶음의 자기 위 방향 오차 > 0.3°. 기존 시험에는 `up_own` 이 전부 `None` 이라는 단언을 더해 두 시험이 서로 다른 갈래를 맡음을 못박았다.
- 실행: 구역의 정밀 포즈(`rposes`)를 사진 번호 % 3 으로 묶어 `up_cross_check` 를 부른다. 위 방향은 좌표계에 무관한 각이라 구역마다 따로 구해도 된다. 구역별 값과 전체 최대, 문턱 초과 여부를 `report.json` 의 `up_cross_check` 객체와 `PipelineResult.up_cross` 에 담고, 알림에 한 줄을 남긴다(초과하면 문구가 달라진다).

## 남은 문제
- 위치 8곳짜리 작은 구역에서는 정밀 모델 자체가 어긋나(광축 사이 각 80°·58°·84° 대 참값 약 50~53°) 어긋남이 수십 도로 나오고 알림이 초과로 뜬다. 구름이 아니라 모델 오차가 원인이므로 이 경우 경고는 거짓 양성이다. 120장 단구역에서는 광축 사이 각이 53.5°·49.4°·50.5° 로 맞는다. 구역이 작을 때 검사를 건너뛰거나 구역별 사진 수 하한을 두는 판단이 필요하다(이번 작업은 동작을 바꾸지 않으려고 하한을 두지 않았다).
- 이 합성 장면은 묶음마다 방위가 한 방향뿐이라 실행 경로에서는 대체(x 축 기울기 평균) 갈래만 돈다. 실제 왕복 비행 자료에서의 실행 값은 아직 없다.
- 대체 갈래 감도는 cos(아래 기울기)에 비례해 연직에 가까운 카메라에서 낮다(F-440 (2)). 이번 작업에서 바꾸지 않았다.
- report.json 의 새 항목을 `verify` 는 읽지 않는다(판정 항목에 넣지 않음).
