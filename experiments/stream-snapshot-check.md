# stream-snapshot-check — 퇴화 입력 정렬 거부, 스냅샷 단조 검사 시험 고정, 점 수별 검사 시간

## 결론
- F-055: 현재 main 에는 임시 닮음 변환(`fn umeyama` 중복·`struct Similarity`)이 없고 `align::robust_similarity`
  기반 `robust_fit` 을 쓴다. 일직선·NaN·짝 0 은 이미 `None` 이었고, 이번에 짝 1·2개, 한 점에 몰린 짝, 대각선
  일직선, 무한 한 점, 전부 NaN, 길이 불일치를 시험으로 더해 모두 `None`(또는 변환 없음) 임을 고정했다.
  일직선 20점에 직선 밖 점 둘을 더하면 변환이 나오고 s = 2 (오차 1e-9 이하).
- F-056: `check_snapshots` 가 정수 단계 점 수 감소·2단계부터 새 영역 0·NaN 을 보고한다. 초벌 > 정밀 장면은 final
  단계에서만 줄면 판정 밖이라 위반이 아니고, 정수 단계에서 줄면 위반으로 보고됨을 실제 장면(3구역, 초벌 6000점·
  정밀 600점)으로 고정했다. 점 수 [100, 1100, 300, 300] → 위반 1건(1100 → 300).
- 큰 점군 속도는 **수 초 기준을 확인하지 못했다.** 4 코어 측정 기계의 부하 평균이 약 45 라 시간이 크게 부풀었다.
  3구역 시험은 선형에 가까움(아래 표), 7구역 × 200만 점은 117~131 s(사용자 CPU 46.7 s, 점군 생성 포함)로
  10 s 시험이 실패했다. 알고리즘 변경은 하지 않았다.

## 방법
- 퇴화 시험은 `align_region`/`robust_fit` 에 위 입력을 직접 넣어 합성 정답(s = 2, 항등 회전)과 비교.
- 단조 시험은 구역 3개 합성 격자(정밀 600점, 초벌 600/6000/600점)로 `for_each_snapshot` 을 돌려 점 수와
  `check_snapshots` 위반 문장을 단언. 초벌이 정밀과 전부 겹치는 장면은 "새 영역 0" 보고를 단언.
- 시간은 측정용 시험(`snapshot_scaling`, `large_snapshot_speed`, 무시 표시)을
  `cargo test --release -p skylens-core --lib stream -- --ignored --nocapture` 로 측정.

## 남은 문제
1. 7구역 × 200만 점 시간이 수 초 기준에 못 미쳤다. 부하가 큰 기계라 확정하기 어렵지만 사용자 CPU 만 봐도 40 s
   안팎이라 해시 삽입(단계마다 정밀 200만 점씩 누적)과 질의가 단일 스레드로 남은 부분이 병목일 가능성이 크다.
   부하 없는 기계에서 재측정하고, 삽입을 구역 단위 병렬 구성 후 합치기로 바꾸는 안을 시험해야 한다.
2. `large_snapshot_speed` 의 10 s 단언은 부하 없는 기계 기준이다. 부하 상태에서는 실패한다.
