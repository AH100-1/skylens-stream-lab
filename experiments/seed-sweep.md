# 시드 3·4·5 새 기본 빌드 재측정과 구역2 13° 기울기의 발생 단계

## 결론

- 새 기본(`pair_vote` 켬, 인자 없는 `run` → `verify`)으로 시드 3·4·5 를 다시 쟀다. 시드 3 은 6/7(preview_vs_refined 만 실패), 시드 4 는 6/7(같은 항목), 시드 5 는 5/7(registered, preview_vs_refined). 시드 4·5 는 투표를 켜도 결과가 이전과 같다.
- 시드 4·5 구역2 의 13° 기울기는 회전 평균·위치·BA 에서 생기지 않는다. 상대 회전은 모든 단계에서 0.1~1.1°(전역 회전을 맞춘 뒤)이고, 정밀 BA 직후 정답 대비 전역 연직 기울기도 0.84°(시드 4 구역2)였다.
  기울기가 12.74° 로 커지는 것은 정밀 BA 뒤 GPS 닮음 정렬(`gps_align_refined`) 한 단계다(같은 구역·같은 모델에서 0.84° → 12.74°).
- 원인은 GPS 중심의 거의 한 직선 배치다. 구역2 의 GPS 퍼짐 표준편차가 (22.9, 3.3, 1.35) m(시드 4), (23.3, 2.1, 1.44) m(시드 5)인데 GPS 잡음 중앙값이 약 2.3 m 라서, 긴 축 둘레 회전(롤)이 잡음에 지배된다. 구역0·1 은 퍼짐이 약간 더 넓거나 사진 수가 많아 2~5° 에 그친다.
  초기화 단계(`sparse_init_roll`)에는 같은 퇴화에 대비한 비행 축 둘레 롤 규칙(광축 높이 분산 최소)이 있으나, 정밀 모델의 `gps_align_refined` 에는 없다.
- 시드 3 도 같은 양상이다: 정밀 BA 직후 전역 기울기가 0.88 / 3.98 / 4.46°(구역 0/1/2)이고 정렬 뒤 2.86 / 4.00 / 4.49° 로 거의 그대로다. 즉 시드 3 의 4° 대는 정밀 BA 의 GPS 사전항 단계에서 이미 생긴다(정렬이 아니라 BA 쪽). 시드 4 구역0 도 BA 뒤 2.20° → 정렬 뒤 2.36°.
- 고치지 않았다. 시간이 모자라 고침 후 재측정을 못 한다. 제안: `gps_align_refined` 에서 GPS 중심이 거의 직선(둘째 주성분 퍼짐 / 잡음 < 약 2)이면 닮음 변환의 회전을 비행 축 둘레만 `roll_by_level_spread` 규칙으로 다시 고르고(이동·척도는 재계산), 직선이 아니면 지금처럼 둔다.
- 시드 5 등록 54/81: 구역별 등록 사진 28/42, 32/48, 10/15(소유 28/32/10). 입력 상대 회전의 5° 초과 간선은 구역1·2 에 1개씩(정상 대응 1080, 남음), 구역0 은 0개. 빠진 사진이 어느 것이고 짝이 몇 개인지는 현재 진단 출력에 없어 특정하지 못했다(미해결).
- 시드 1·2 는 시간이 없어 재지 않았다.

## 방법

- 제품 feat/seed-sweep(feat/seed3-collapse 63e5056 위). 명령: `SKYLENS_TILT_SEED=<시드> RAYON_NUM_THREADS=2 cargo test --release -j 2 -p skylens-stream --test default_tilt -- --ignored --nocapture`.
- 진단 추가(환경 변수 `SKYLENS_REGION_DIAG` 있을 때만, 기본 동작 불변): GPS 정렬 직후 사진 자세 단계 `aligned`, 시험 쪽에서 단계마다 전역 회전 Q 의 각과 연직 기울기 출력.
- 시드 5 는 정렬 단계 진단을 넣기 전 빌드, 시드 3 은 넣은 뒤 빌드로 쟀고, 시드 4 는 두 빌드로 모두 재서 결과가 같다.

## 남은 문제

- `gps_align_refined` 의 직선 배치 퇴화 대응(위 제안) 구현과 시드 1~5 재측정.
- 시드 3·4 구역0·1 의 2~4° 는 정밀 BA 의 GPS 사전항 단계에서 생기는 것으로 보이며(시드 3), 이쪽 원인은 따로 봐야 한다.
- 시드 5 등록 실패 사진의 특정(사진별 짝 수 출력 필요). 시드 1·2 재측정.
- preview_vs_refined 가 시드 3·4·5 모두 실패(높이 차 2.8~3.4 m): 초벌 대 정밀 높이 차는 기울기와 같은 원인일 가능성이 있으나 확인 못 함.
