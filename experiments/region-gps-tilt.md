# 구역0 GPS 정렬이 남기는 2.4° 기울기의 원인 분리와 연직 고정 옵션

## 결론

- 구역0 의 기울기 2.43° 는 GPS 잡음이 경로 축 둘레 회전(롤)을 못 정하기 때문이다. 구역0 카메라 중심은 한 평면(고도 거의 일정)에 놓여 가장 작은 축 표준편차가 0.00 m 이고, 긴 축 15.0 m, 중간 축 4.3 m(중간/최대 0.29)뿐이다. GPS 잡음은 수평 rms 2.09 m, 높이 rms 1.50 m 라, 정답 중심에 같은 크기(2 m) 모의 잡음을 얹어 20회 정렬하면 평균 기울기가 구역0 위치에서 2.36°, 구역1 위치에서 2.63° 다. 즉 기대 기울기 자체가 2.4° 근처이며 구역0 의 2.43° 는 이 범위 안의 한 번 뽑기다(구역1 은 0.16° 로 운이 좋았다).
- 후보별 기여(구역0, 평균 기울기): 기본 2.426° → 트리밍 없이도 2.426°(트리밍 (iv) 기여 0: 정상 150/150) → 정답 중심으로 정렬 1.425°(남는 1.4° 는 정렬 직전 초벌 모델 자체의 비틀림 (iii)) → GPS 수평만 정답으로 바꾸면 2.400°, 높이만 정답으로 바꾸면 1.454°. 기울기는 대부분 GPS 높이 잡음에서 온다(높이 잡음 제거로 2.43 → 1.45). 같은 분해로 구역1: 0.157 → 정답 중심 0.085 (모델 비틀림 작음).
- 작은 수정(옵션 gps_fixed_up, 기본 꺼짐): 정상 대응 선별 뒤, 사진 회전에서 연직(카메라 x 축이 수평이라는 짐벌 가정, 기존 up_from_rotations)을 구하고 기존 similarity_fixed_up 으로 방위·배율·평행이동만 푼다. 구역0 정렬 직후 기울기 2.426° → 0.348°, 구역1 0.157° → 0.035°. 정답 중심 + 연직 고정이면 구역0 0.249°, 구역1 0.042° 라 남은 것은 모델 비틀림이다.
- 제품 지표(옵션 켠 실행, 4 코어 측정 기계 한 번): 표면 중앙 0.147 m (기준 0.151), refined_overlap 중앙 최대 0.152 m (같음), verify 7/7, 카메라 중심 중앙/최대 0.192 / 0.523 m (기준 0.190 / 0.701). 나빠지지 않았다. 옵션을 끈 기본은 pipeline·pipeline_regions 시험 8개 모두 통과(동작 불변).

## 방법

- 정렬 직전(정밀 BA 직후) 구역별 자세와 사진별 GPS 를 꺼내는 진단 훅(기본 꺼짐)을 추가하고, 시험이 같은 입력으로 변형들을 오프라인에서 다시 맞춰 R_tᵀ(R·r⁻¹) 의 극분해 평균 회전각을 쟀다. 정답 중심과 GPS 는 같은 첫 GPS 좌표계. 모의 잡음은 정답 중심 + 축별 N(0, σ²), 고정 시드 20회.
- 시험: crates/cli/tests/region_gps_tilt_diag.rs 의 gps_tilt_causes (무시 표시, 환경변수 GPS_UP 설정 시 옵션을 켜고 파이프라인 정렬 직후 기울기를 잰다, 약 105 s).

## 남은 문제

- 연직 고정은 카메라 x 축이 수평(짐벌)이고 보는 방위가 퍼져 있다는 가정이다(up_from_rotations 가 문턱을 못 넘으면 자동으로 기존 정렬로 돌아간다). 짐벌이 없는 실제 데이터에서는 확인하지 못했다.
- 구역0 에 남은 0.25~0.35° 와 사진별 흩어짐 0.34° 는 초벌 모델의 비틀림이라 정렬로는 못 줄인다. 연쇄 변환 뒤 구역 간 회전 차에 이 옵션이 얼마나 영향을 주는지는 이번에 재지 않았다.
- 한 장면, 한 번 측정, 모의 잡음은 20회뿐. 기본 켜기 판단에는 다른 장면(경로 모양·잡음 크기)이 필요하다.
