# P11b fusion-tests — 깊이 융합 시험 판별력·편대 장면 (F-112·F-069·F-070·F-113)

## 결론
F-069 은 확인 기준(실측 편대 42장·σ 0.1%·이상치 10%에서 0.3 m 초과 0점, 최대 < 0.1 m)을 처음으로 맞췄다. 방법은
**동의 사진이 기준 사진과 다른 촬영 무리(드론)를 하나 이상 포함해야 한다**는 조건(`min_groups` 기본 2)이다. 최대 오차
11.74 m → 0.057 m, 0.3 m 초과 1 → 0. 대가로 점 수가 503187 → 15684 로 3% 남짓만 남는다(서로 다른 드론 시선이 겹치는
지면만 남음). 즉 떠 있는 점 문제는 풀렸지만 밀도 문제가 새로 생겼다 — 채택 여부는 밀도 쪽 결정이 필요하다.
또 `view_selection::select_neighbors` 가 고른 이웃 8장은 실측 편대에서 **모두 같은 드론 사진**이어서(F7 이웃 [39,3,36,0,6,33,9,30])
무리 조건과 함께 쓰면 점이 0 이 된다. 편대 시험은 전체 사진 대조로 돌린다.
F-112 는 과제가 지정한 네 단계 중 법선 일관성 검사를 거르는 시험이 없었으므로 새로 넣었다. 변이 실행은 기계 부하(부하 평균 60~80)
때문에 마감 안에 일부만 끝났다(아래 표). F-113(병렬화·시간)은 손대지 못했다.

feat/fusion-hardening + main 병합(c47f777) 의 시험 8개(무시 2개 제외).

정답 5285점·중앙 2.9e-8, 잡음 4620점·중앙 0.00108(단일 0.00198)·최대 0.0123.

## 방법
- 변이: 왕복 투영 검사 끔(`if false && ...`), 상대 깊이 검사 끔, 최소 동의 수 끔(필요 수 1), 법선 일관성 검사 끔.
  나머지 다섯 변이(쓰인 화소 표시 제거, 이웃 `used[j]` 검사 제거, 법선 세계 변환 제거, 기준 색만, 위치 평균 제거)도
  사본을 만들었지만 기계 부하 때문에 마감 안에 빌드를 끝내지 못해 중단했다.
- 법선 일관성만 거르는 시험 `normal_check_rejects_tilted_normals`: 시선이 비슷한 3장(0.3 간격)에서 깊이는 정답 그대로,
  사진 0 법선만 카메라 x 축으로 20°/45° 돌린다. 기준각 30° 이므로 20° 는 깨끗한 경우와 점 수가 같고 45° 는 0 점이어야 한다.
- 무리(드론) 조건: `FusionView.group: Option<u32>`, `FusionConfig.min_groups`(기본 2). 기준 사진과 동의 사진이 걸친
  서로 다른 무리 수가 `min_groups` 이상이어야 점을 만든다. 무리가 `None` 인 사진은 저마다 한 무리로 센다(기존 호출은
  그대로 동작). 근거: 2차 추적에서 떠 있는 점은 모두 같은 드론 이웃 3장이 같은 배율 s 로 틀려 z = 30(1 − s) 평면에서
  동의한 것이다. 다른 드론은 방향(±120°)이 달라 같은 배율이 같은 3D 점으로 모이지 않는다.
- 편대 시험은 위치마다 F·R·L 순서이므로 무리 = 사진 번호 mod 3.

## 남은 문제
1. 무리 조건 뒤 실측 편대 점 수가 3% 로 줄었다. 같은 드론 사진만 보이는 지면이 대부분이라서다. 대안: (a) 같은 무리 사진만
   동의한 점은 버리지 말고 깊이 비율 분포(같은 배율 이상치는 z = 30(1−s) 가짜 평면)로 따로 거르기, (b) 같은 무리 동의일 때만
   더 엄격한 상대 깊이·더 많은 동의 수 요구, (c) 이웃 선택이 다른 드론 사진을 일부 포함하도록 고치기(view_selection 쪽).
2. `select_neighbors` 이웃 8장이 실측 편대에서 모두 같은 드론이다. 무리 조건과 이웃 제한을 함께 쓰려면 이웃 선택에 무리 다양성이 필요하다.
3. F-112 변이 9종 중 나머지(측정 못 함 표시)는 다시 돌려야 한다. 사본 생성 스크립트는 단순 문자열 치환이라 그대로 다시 쓸 수 있다.
4. F-113: 손대지 못했다. 48장 960×540 시간 시험은 여전히 무시 상태(이전 측정 20.8 s, 부하 상태).
