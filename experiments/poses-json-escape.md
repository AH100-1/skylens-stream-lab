# 포즈 JSON 쓰기: 이름 이스케이프와 비유한 포즈 처리 (F-320)

## 결론
포즈 파일의 이름이 따옴표·역슬래시·제어 문자·한글이 섞여 있어도 쓰고 읽은 이름이 원래와 한 글자도 다르지 않게 되었다. 회전·중심에 NaN·inf 가 든 포즈는 파일에서 빼서, 카메라 한 대 때문에 파일 전체를 못 읽는 일이 없어졌다. 쓰기를 오류로 올리는 방안은 택하지 않았다(아래 방법 참고).

## 수치 표
| 시험 | 입력 | 기준 | 결과 |
|---|---|---|---|
| 이름 왕복 | 이름 5개(`a"b.jpg`, `dir\sub\c.jpg`, 한글+공백, 탭·개행·U+0001·U+001F 포함, `\"\` ) | 읽은 이름 5개가 원래와 완전히 같음, 구조체 전체 동일 | 5/5 일치 |
| 쓰인 글자 | 위 파일 | `a\"b.jpg`, `dir\\sub`, `\u0001` 포함, 한글은 그대로 | 통과 |
| 비유한 포즈 | 4개 중 중심 NaN 1개, 쿼터니언 inf 1개 | 글자 `NaN`·`inf` 없음, 남는 이름 `["a","b"]`, 남은 중심 오차 < 1e-9 | 통과 |
| 기존 시험 | 왕복·변환·잘못된 JSON | 그대로 통과 | 5개 시험 모두 통과 |

## 방법
- 이전 쓰기는 이름의 `"` 를 `'`, `\` 를 `/` 로 바꿔 썼다. 이를 JSON 문자열 이스케이프로 교체: `"`→`\"`, `\`→`\\`, U+0000–U+001F 는 `\u00xx`. 한글 등은 UTF-8 그대로 둔다.
- 읽는 쪽(`stream.rs` 의 손으로 짠 해석기)은 `\"`, `\\`, `\uXXXX` 를 이미 해석하므로 읽기 코드는 고치지 않았다. 시험으로 확인했다.
- 비유한 포즈: 호출부(`pipeline.rs`)는 `write_poses_file(...)?` 로 쓰기 오류를 파이프라인 전체 실패로 올린다. 오류로 하면 등록이 틀어진 카메라 한 대가 구역 전체 실행을 멈추므로, `to_json` 에서 해당 포즈만 건너뛰도록 골랐다. 수치는 `{:?}` 그대로(유한값은 유효한 JSON 수치).

## 남은 문제
- 건너뛴 포즈를 기록하는 곳이 없다. 호출부에서 개수를 경고로 남기려면 `pipeline.rs` 를 고쳐야 해서 이번 범위 밖.
- 내부 파라미터(fx 등)가 비유한이면 여전히 `NaN` 글자가 써진다. 이 경우는 건너뛸 대상이 없다.
- 읽기 해석기는 서로게이트 쌍 `😀` 을 하나의 글자로 합치지 못한다. 쓰기는 비ASCII 를 그대로 쓰므로 이 파일들에서는 문제가 없고, 외부에서 만든 파일에만 해당.
- 이 작업은 PR #55(`feat/pipeline-poses`)가 아직 병합되지 않아 `poses_io.rs` 가 main 에 없으므로 그 브랜치 위에 쌓았다. #55 가 병합되면 그대로 올릴 수 있다.
