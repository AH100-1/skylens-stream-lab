# 덩어리 잇기(SKYLENS_ROT_BRIDGE=1)가 기본 경로 verify 를 얼마나 고치는가

## 결론
- 시드 3 기본 경로에서 덩어리 잇기를 켜면 verify 는 5/8 → 7/8 이 된다. 8/8 은 아니다. 세 실패가 한 뿌리가 아니다.
- 같은 뿌리인 것: 위 방향 일치(구역 0 최대 어긋남 69.509° → 0.894°)와 preview_align(스케일 차 25.41% → 0.26%, 잔차 중앙 최대 2.102 → 0.455 m).
  구역 0 의 L 묶음 회전 오류가 초벌 정렬 스케일과 위 방향 둘 다를 흔들었고, 회전 평균에서 묶음을 바로잡으면 둘 다 한꺼번에 통과한다.
- 다른 뿌리가 남은 것: preview_vs_refined 는 켜도 실패다(최근접 중앙 최대 3.151 → 2.973 m 로 문턱 3 m 아래로 내려갔지만, 높이 차 중앙 최대 4.360 → 3.289 m 로 문턱 2 m 위).
  구역별로 재면 켠 뒤에도 구역 0 과 구역 1 이 모두 문턱 근처이며, 구역 1 은 켬/끔 모두 나쁘다(아래 표). 구역 1 에는 위 방향 오류가 없으므로 회전 오류만으로는 설명되지 않는다.
- 시드 1 에서 켬은 verify 통과 수를 바꾸지 않는다(끔 8/8, 켬 8/8). 다만 통과 안의 수치는 나빠졌다: preview_vs_refined 최근접 0.473 → 0.737 m, 높이 차 0.310 → 0.727 m.
  나머지 항목(스케일 차 5.84 → 5.73%, 겹침 0.119 → 0.092 m, 위 방향 0.577° → 0.176°)은 비슷하거나 좋아졌다. 문턱 안이지만 "나쁘게 하지 않는다"고 말하기는 어렵다.

## 방법
- 제품 feat/zone0-rot(6f369fa)에 main(위 방향 일치 8번째 항목 포함)을 병합한 브랜치를 release 로 빌드(4 코어 측정 기계, 다른 빌드와 동시).
- 시험 `crates/cli/tests/rot_bridge_verify.rs`(무시 시험): 시드별 `Scene::new(SceneConfig{seed,..default})` 로 장면을 쓰고, `run`(끔은 환경 변수 제거, 켬은 `SKYLENS_ROT_BRIDGE=1`) 뒤 `verify` 를 돌려
  `/tmp/rbv-<시드>-<on|off>/{in,out,run.txt,verify.txt}` 에 남긴다. 실행: `RBV_SEEDS=3,1 RBV_MODES=off,on cargo test --release -p skylens-stream --test rot_bridge_verify -- --ignored --nocapture`.
- run 한 번 약 140~190 초(부하에 따라). 시드 1 끔은 두 번 돌려 verify 수치가 완전히 같음을 확인(재현성).
- 구역별 표는 PLY 를 읽어 파이썬으로 점 약 1500 개를 뽑아 3차원 최근접 중앙값과 수평 2 m 안 가장 가까운 점의 높이 차 중앙값을 낸 근사다(verify 의 표본 추출과 달라 값이 조금 다르다: 시드 1 끔 구역 0 최근접 0.611 대 verify 최대 0.473).

## 남은 문제
- 시드 3 의 preview_vs_refined 는 켜도 남는다. 구역 1(위 방향 정상)에서도 초벌-정밀 높이 차가 2.3~2.7 m 이므로, 초벌 점군 자체(조밀 융합 또는 구역 1 정렬)의 문제를 따로 봐야 한다. 구역 0 과 구역 1 이 같은 뿌리인지는 이 측정으로 알 수 없다.
- 시드 1 에서 켬이 초벌-정밀 차이를 키운 원인(구역 0 높이 차 0.29 → 0.74 m)은 밝히지 못했다. 시드 2 와 정밀 BA 뒤 L 묶음 회전 오차는 이번에도 재지 않았다.
- 시드 하나씩만 돌려 켬의 득실을 일반화할 수 없다. 기본값을 켬으로 바꾸기 전에 시드 2·4·5 가 필요하다.
