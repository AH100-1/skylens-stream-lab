# 기본 경로 구역 기울기: cf84b80 에서 구역0 30.7° 가 남는가

## 결론

- 남지 않는다. 제품 브랜치 feat/region-cross-extend(cf84b80) 에서 인자 없는 synth → run → verify 는 종료 0, 7/7, 등록 81/81(초벌·정밀) 이고,
  구역별 평균 회전 오차는 0.92 / 1.30 / 1.65°, 연직(위 방향) 기울기 중앙은 1.00 / 1.15 / 1.43° 다. 구역0 의 30.7° 에 해당하는 값은 없다.
- 30.7° 는 main 에서 구역0 이 42장 중 14장만 등록되던 상태(region-cross-extend 노트: 고치기 전 구역 0 등록 14/42)와 같은 조건의 값으로 보인다.
  cf84b80 에서는 구역0 이 42/42 등록되고 GPS 정렬에 68장(소유 42 + 보조 26)이 들어간다. 이번에 main 을 다시 재지는 않았으므로 "등록이 모자라서 기울기가 틀어졌다"는 것은 정황 판단이다.
- 따라서 `--gps-fixed-up` 같은 연직 고정 옵션은 이 경로에 필요하지 않다. 이번에 고친 것은 없다.
- 남는 오차는 GPS 잡음 한계 수준이다(아래 GPS 정렬 표: 잔차 중앙 2.2~2.4 m, 중심 퍼짐 둘째 축 3~5 m). 정렬에 쓰인 사진 수와 퍼짐으로 추정한 기울기 불확실도는 약 2.3°(구역0)이며 실측 1° 는 그 안이다.

## 수치 표

## 방법

- 제품 feat/default-tilt(cf84b80 위 한 커밋)를 release 로 빌드. 환경 변수 `SKYLENS_REGION_DIAG` 가 있을 때만 구역 정밀 모델 완성 직후(GPS 정렬 직후)의 사진별 회전과 정렬 요약을 표준 오류로 낸다. 없으면 동작 불변.
- 기울기: 사진마다 정답 회전 R_t(truth/cameras.txt)와 추정 회전 R_e 로 R_eᵀ R_t 를 만들어 소유 사진 전체의 평균 회전(극분해)의 각을 쟀다(평균 회전 오차).
  연직 기울기는 정답 카메라 좌표의 위 방향 R_t·e_z 를 추정 회전으로 세계로 되돌린 R_eᵀ R_t e_z 와 e_z 의 각의 사진별 중앙. 출력 좌표와 정답 좌표는 원점만 다르고 축 방향이 같다.
  gps-up-seeds 노트의 기울기는 앞쪽 방식이라 표의 '평균 회전 오차' 행끼리 비교한다.
- 정렬 요약의 '잔차 3 m 이하'는 정렬 뒤 모델의 사진 중심과 GPS 거리를 다시 계산해 3 m 이하를 센 것이다(강건 추정의 정상 대응 마스크 자체가 아니라 근사).
  GPS 퍼짐은 등록된 사진의 GPS 위치(동-북-위) 공분산의 표준편차.
- 표면 중앙·중심 오차는 기존 시험 default_path 의 값(같은 계산), verify 는 명령행.
- 기울기 불확실도 추정: 축당 잡음 σ ≈ 잔차 중앙/1.538, 오차 ≈ σ / (둘째 축 표준편차 · √N) = 1.45 / (4.89 · √53) rad ≈ 2.3°(구역0).

## 남은 문제

- main(6a8bb90) 을 이번에 직접 다시 재지 않아, 30.7° 가 구역0 14/42 등록 때문이라는 설명은 확인이 아니라 정황이다. main 에서 같은 진단 출력을 붙여 구역0 의 등록 수·퍼짐·잔차를 재면 닫힌다.
- 한 번씩 잰 값이다. 시드 하나(기본 시드 1)뿐이라 흔들림 폭은 모른다.
- 기울기 1~1.4° 는 GPS 잡음 한계(추정 불확실도 약 2.3°)와 같은 크기라, 연직 고정으로 줄일 수 있는지는 이 경로에서 따로 재지 않았다.
- 구역0 의 잔차 3 m 이하 사진은 68장 중 53장뿐이다. 잔차 중앙이 2.2 m 로 큰 이유(합성 GPS 잡음 설정 자체인지, 모델 척도 오차인지)는 가르지 않았다.
- 진단은 구역 정밀 모델 완성 직후 값이다. 이후 구역 간 재정렬이 걸리면 출력 poses 와 다를 수 있다(poses.txt 에 회전이 없어 최종 회전은 못 잼).
