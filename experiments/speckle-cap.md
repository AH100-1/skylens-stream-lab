# 반점 크기 문턱 상한과 반점 제거 정리 (speckle-cap)

## 결론
- 반점 크기 문턱에 상한 400 화소를 두었다. 960×540 이하는 이전 식과 같고(출력 불변), 그 위에서만 바뀐다. 1920×1080 은 1600 → 400 이다. 400 은 960 에서 100 화소 고정보다 중앙·95% 가 모두 낫다고 잰 값이라 근거가 있는 상한이다.
- 합성 1920×1080 지도에서 가는 참 구조물(8×120 = 960 화소 기둥)이 상한 없이는 지워지고(문턱 1600) 상한 400 에서는 남는다. 진짜 반점(3×3)은 여전히 지워진다. 이 점은 단위 시험으로 단언했다.
- 너비 1920 에서 실제 점 수·표면 95% 를 960 과 비교하는 끝까지 측정은 하지 않았다(미측정). 대신 상한으로 1920 의 문턱이 960 과 같아졌으므로 문턱 영향은 960 에서 잰 것과 같은 크기이고, 면적 비례 증가분(1600)만 막았다.
- 상대 깊이차를 `|d1 - d2| < rel · min(d1, d2)` 로 대칭화했다. 훑는 순서·좌우 배치와 무관하게 같은 결과이고 문턱 동치 시험도 네 배치에서 같다.
- 길이 불일치를 `Err(BadMapLen)` 로 구분했다(`Ok(0)` 은 "지운 것 없음"). 구역 보고(`DenseReport`)에 잘못된 지도 수와 융합 오류가 남는다.
- 융합 법선 각을 `DenseConfig::normal_deg` 로 뺐다(기본 25.0 그대로).

## 수치 표
기본 경로 출력이 바뀌는 범위(문턱 함수 값, 16:9):

| 너비 | 이전 문턱 | 새 문턱 |
|---|---|---|
| 480 | 100 | 100 |
| 960 | 400 | 400 |
| 1280 | 711 | 400 |
| 1920 | 1600 | 400 |
| 3840 | 6400 | 400 |

1920×1080 합성 지도(벽 300×300, 기둥 8×120, 반점 3×3 두 개):

| 항목 | 이전 문턱(1600) | 새 문턱(400) |
|---|---|---|
| 유효 화소 | 90 978 | 90 978 |
| 지워진 화소 | 기둥 포함 960+18 = 978 (식으로 계산, 기둥 960 < 1600) | 18 (반점만) |
| 기둥 보존 | 아니오 | 예 |
| 399 화소 조각 | 지움 | 지움 |

법선 각 설정 시험(96×54, 4 위치 12장, 스윕): 25° 점 1158, 1° 점 237. 기본값 시험 결과는 설정 없이 부른 경로와 점 수가 같다. 반점 제거 비율 0.389(이 해상도 지도가 작아 비율이 크다).

## 방법
- F-431: 무시 측정 `speckle_share_and_time_by_width` 의 단언을 문턱이 100 이상이면 `share >= fixed_share`, 미만이면 `<=` 로 바꿨다. 960 에서 문턱이 400 이라 고정 100 보다 더 지우는 것이 맞다. 이 무시 측정 자체는 4 코어 측정 기계가 과부하라 돌리지 못했다(미실행).
- F-396: 분모를 `min(d0, dj)` 로 대칭화. 8/10 두 깊이를 큰 쪽·작은 쪽이 왼쪽·오른쪽에 오는 네 배치로 놓고 rel 0.25(동치, 분리)·0.22(분리)·0.26(합쳐짐)을 확인한다. `<` → `<=` 변이는 기존 문턱 동치 시험이 계속 잡는다.
- F-397/F-434: 길이 검사를 `w.checked_mul(h) != Some(len)` 로. w=usize::MAX, h=2, 길이 0 은 패닉 없이 Err. 짧은 지도를 내는 추정기로 구역 보고에 "배열 길이"·"융합 실패" 가 남는 것을 확인한다. 무효 비용은 패치매치 어댑터에서 깊이 없는 화소를 INFINITY 로 통일(`mark_invalid_cost`).
- F-433: 자세 잡음 시험이 모듈의 `speckle_min_px`·`remove_speckles` 를 직접 쓴다(식이 하나). 12장·96×54 상시 시험을 더했다. 상시 시험 실측: 기본 경로 점 594·중앙 0.1220·95% 0.4683, 최소 8도 경로는 이 크기에서 점 0(경로가 죽지 않는지만 단언). 8도 경로의 수치 단언은 여전히 무시 시험에만 있다.
- 측정 환경은 4 코어 측정 기계이고 다른 작업이 동시에 돌아 부하가 높았다. 시험은 release.

## 남은 문제
- 너비 1920 점 수·표면 95% 직접 측정(F-432 확인 기준)과 F-431 무시 측정 실행은 하지 못했다.
- 구역별 보고(`DenseReport`)를 파이프라인 결과로 올리는 연결은 하지 않았다(`region_cloud_report` 로 얻을 수 있음). 파이프라인 수정이 필요하다.
- F-433 의 view_selection.rs 사진별 모드 footprint 중복 계산은 맡은 파일 밖이라 손대지 않았다.
- 길이 불일치 반환형이 `usize` 에서 `Result` 로 바뀌어 호출부 두 곳(모듈 내부, 자세 잡음 시험)을 고쳤다.
