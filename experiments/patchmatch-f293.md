# 회차: 건너뜀 문턱(skip_cost) 0 / 0.08 비교, 깊이 너비 192 px (2026-10-03, 4 코어 측정 기계)

## 결론
- 끝까지 흐름(단구역 합성 장면, 깊이 너비 192 px)에서 건너뜀 0 과 0.08 의 융합 점 수·점→표면 중앙·95%·1 m 초과 비율이 완전히 같다(57,724 점, 0.470 m, 3.061 m, 10.42%). 이 장면·너비에서는 건너뜀이 최종 점군에 영향을 주지 않는다. 그래서 흐름 수준의 표만으로는 기본값 0.08 을 정당화할 수도, 반대할 수도 없다.
- 영향이 보이는 곳은 패치매치 단독(편대 지면 장면, 960×540, 이웃 8장)이다: 건너뜀 0 은 1% 이내 98.6%·법선 2.83°, 0.08 은 94.4%·법선 4.01°. CPU 시간은 3.12 s 대 1.74 s 로 0.08 이 44% 적다. 기본값 0.08 의 근거는 속도(F-048 시간 목표)이고, 대가는 1% 이내 비율 4.2 %p 와 법선 1.2° 이다.
- 따라서 기본값 0.08 은 "속도 대가로 단독 정확도 4.2 %p 를 내준다" 는 선택으로 유지하되, 흐름 수준에서 손실이 없다는 확인은 이 장면에서 건너뜀이 작동하지 않았다는 점 때문에 아직 약하다(아래 남은 문제). F-293 의 확인 기준 중 "끝까지 흐름 표"는 만들었으나 두 설정이 구분되지 않아 근거로는 불충분하다.

## 방법
- 패치매치 단독: 빌드 `cargo test --release`, 환경 변수 `PM_SK=0` / `PM_SK=0.08` 로 `fast_960 --ignored --exact --nocapture`. CPU 시간은 `/proc/self/stat` 의 사용자+시스템.
- 흐름: 기존 `patchmatch_skip_cost_compare` 시험(`--ignored`)을 그대로 쓰되, 측정용으로 시험 파일에서 깊이 너비·장면 크기를 환경 변수(`PIPE_DW`, `PIPE_SW`, `PIPE_SH`)로 바꿀 수 있게 로컬에서만 고쳤다(커밋하지 않음). `PIPE_DW=192`, 장면 기본 320×180, 간격 2, BA 15회, 점수는 최종 `step_final_all_refined.ply`.
- 건너뜀이 흐름에서 작동하지 않는 이유는 확인하지 못했다. 가능한 원인: 깊이 너비 192 의 가장 거친 층 외 층이 작아 건너뜀 후보(최고 해상도 층에서만 비용이 문턱 아래)가 거의 없거나, 융합 단계의 일관성 검사가 건너뛴 화소를 어차피 걸러 최종 점이 같아진다.

## 남은 문제
- 건너뜀이 정말 작동했는지 확인이 필요하다: 흐름 실행 안에서 건너뛴 화소 수를 세어 찍어 본다. 0 이면 이 비교는 무의미하다.
- 더 큰 입력(깊이 너비 480 이상, 장면 960×540)에서 다시 재야 한다. 이번 장면(320×180)은 깊이 지도가 작아 한계가 있었고, 시간 제약(한 번에 약 5~7분, 부하 16)으로 더 크게 못 돌렸다.
- 대안 가설(미측정): '건너뜀' 대신 이미 좋은 화소의 섭동 폭만 줄이기. 질감 없는 화소(가중 분산 < 4e-4)는 방문하지 않되 저해상도 층 깊이를 사전으로 남겨 구멍을 메운다. 이미 좋은 화소는 반복에서 빼지 않고 비용 c = 1 − NCC 가 0.6 이하면 섭동 폭 1/4, 0.8 이하면 1/2 로 줄이고, 개선될 때마다 폭을 절반으로 한다. 이렇게 하면 1% 이내 비율 손실 없이 속도를 얻을 수 있다는 가설이다. 검증 기준: `fast_960` 1% 이내 ≥ 98%, CPU ≤ 2 s.
- 부하가 낮은 기계에서의 벽시계 재측정(F-292 와 공통).
