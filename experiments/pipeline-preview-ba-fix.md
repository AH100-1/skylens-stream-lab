# 초벌 BA 옵션 시험 실패 원인 (preview_ba_option_does_not_change_refined)

## 결론
- 원인은 (a)(b)(c) 어느 쪽도 아닌 시험 틀의 경쟁 상태였다. `run_case` 가 작업 폴더를 `프로세스번호 + 인자` 로만 만들어, 인자가 같은 시험 둘(`synthetic_single_region_end_to_end`: stride 2, BA 15, Sweep, 초벌 BA 0 / 이 시험의 a 실행)이 같은 프로세스에서 병렬로 돌면 같은 폴더를 지우고 다시 쓰며 서로의 입력·출력을 덮었다.
- 단독 실행에서는 통과하고 초벌 BA 0회와 8회의 정밀 결과가 완전히 같아(중심 오차 중앙 0.3284 m, 최대 2.9124 m) 초벌 BA 가 공유 상태를 바꾸는 버그의 증거는 없다. 시험 가정도 그대로 유효하다.
- 수정: 작업 폴더 이름에 시험 이름(스레드 이름)을 넣어 시험마다 분리. 단언은 그대로(완화 없음).

## 수치
| 실행 | 초벌 BA 0 중앙/최대 (m) | 초벌 BA 8 중앙/최대 (m) | 결과 |
|---|---|---|---|
| 단독 (4 코어 측정 기계, 기본 스레드) | 0.3284 / 2.9124 | 0.3284 / 2.9124 | 통과 (265 s) |
| 파일 전체 병렬, 수정 전 | - | - | 실패 (재현) |
| 파일 전체 병렬, 수정 후 | - | - | 통과 |

정밀 재투영 0.300 px (초벌 0.310 px), 판정 7/7.

## 방법
- 시험 위치 `crates/cli/tests/pipeline.rs`. 단독 실행으로 통과를 확인한 뒤 같은 파일의 시험 5개를 함께 돌려 실패를 재현했다.
- 폴더 충돌 가설은 두 시험의 인자가 같다는 점과 폴더 이름 구성으로 확인했다.

## 남은 문제
- RAYON_NUM_THREADS=1 과 4 의 결과 비교는 마감 때문에 끝내지 못했다(1 스레드 실행은 시작만 함, 미확인). 수정 후 파일 전체의 나머지 시험(두 구역 등 장시간)은 마감 시점에 끝나지 않아 통과를 확인하지 못했다.
- 수정 전 실패 메시지 원문은 나머지 시험이 끝나야 출력되어 보지 못했다.
