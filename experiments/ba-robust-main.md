# 번들 조정 견고성 (main 기준 재적용): F-162·F-164·F-165·F-259

## 결론

네 항목을 모두 현재 main 의 `crates/core/src/ba.rs` 에 고쳤다. 정상 장면(시드 11~13)의 최종 RMS 는
변하지 않았다(0.6234 / 0.6250 / 0.6186, main 값과 같음). 예전 브랜치의 커밋 995020e 는 시험 하나의
무시 사유 문구만 바꾸는 한 줄 수정이라 옮길 내용이 없었고, 네 항목은 현재 코드에서 새로 고쳤다.

## 방법

- F-162: RMS 분모가 0 이면(투영된 관측 0개, 관측 자체가 없는 경우 포함) NaN.
- F-164: 게이지를 트랙 선택·중복 제거 뒤에 계산한다. 축척 고정 후보는 선택된 관측을 가진 카메라만,
  고정 카메라와 점을 공유하는 카메라를 먼저 보고 없으면 나머지 후보.
- F-165: 선택은 점별 서로 다른 카메라 수 2 이상(정렬 기준도 카메라 수). 같은 (카메라, 점) 중복은
  첫 관측만 남기고 나머지는 `num_observations_rejected` 에 더한다.
- F-259: 유효 사전 위치의 공분산 둘째 고유값이 평균 σ² 보다 작으면 직선(첫째 고유벡터)이라 보고
  `BaReport.prior_degenerate` 를 참으로 한다. 직선 둘레 회전 한 자유도는 두 겹으로 막는다.
  (1) 헤세 특이성 제거: 카메라 k 의 회전 증분 성분 하나(−R_k u 에서 가장 큰 성분)를 매 반복 0 으로 고정.
  (2) 이것만으로는 반복마다 슬라이스가 달라져 해가 λ0 에 의존했다(중심 차 4e-3 m). 그래서 받아들인
  후보마다 문제 전체를 직선 둘레로 돌려 기준 카메라의 한 좌표축 각을 처음 값으로 되돌린다. 직선 위
  사전항 비용은 이 회전에 불변이다. (2)를 넣어 4e-3 m → 3e-9 m.
- BaReport 에 필드 하나(`prior_degenerate`)를 추가했다. 호출 쪽에서 BaReport 를 직접 만드는 곳은 없어
  다른 파일은 고치지 않았다. `layout`·`gauge` 는 관측 목록을 인자로 받게 바꿨고 내부 시험 호출 두 곳만 맞췄다.

## 남은 문제

- 사전 위치가 정확히 직선이 아니고 데이터와도 어긋나는 장면(중심 y,z ±4 를 0 으로 눌러 둔 입력)에서는
  λ0 두 값의 해 차가 1.5~2e-6 m 였다. 비용이 부동소수 바닥(상대 1e-14)에 닿아 약한 방향이 풀리지 않는
  것으로 보이며 게이지 문제는 아니다. 기준 1e-6 m 는 직선과 모순 없는 장면에서 확인했다.
- 거의 직선(λ2 < σ²)인 경우의 회전 정규화는 비용이 직선 둘레 회전에 정확히 불변이 아니므로 근사다.
- 고정 카메라 자체가 관측이 없는 경우는 다루지 않았다.
