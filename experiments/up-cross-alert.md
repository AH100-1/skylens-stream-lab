# 교차 검사 초과 알림: 원인 카메라 이름과 정보 줄 분리 (F-445)

## 결론
- 문턱을 넘을 때만 알림 목록(issues)에 한 줄을 넣고, 문구에 최대 어긋남 묶음의 카메라 이름(camF/camR/camL), 구역, 값, 다음 값과의 차를 적는다.
- 문턱 이하이면 issues 에는 아무것도 넣지 않고 events 에 정보 한 줄만 남긴다. 정상 실행의 알림 수는 0 이 된다.
- report.json 의 up_cross_check 형식은 그대로다.
- 한계: 이름은 어긋남 최댓값 기준이라 구름 낀 묶음을 확정하지 못한다(아래 표).

## 수치 표
| 장면 | 묶음별 어긋남(도) | 알림 |
|---|---|---|
| 구름 없음 (합성 기본 120장) | 0.080 / 0.076 / 0.089 | issues 에 없음, events 에 정보 줄 |
| 한 기체 구름 2° (시험 출력 값) | 1.116 / 0.849 / 0.849 | camF 지목, 다음 값과의 차 0.267° |
| 한 기체 구름 2° (띠 배치 시드 0, camF 에 구름) | 0.993 / 0.956 / 1.077 | 최대인 camL 이 지목됨(오지목) |

## 방법
- UpCrossReport::from_checks 로 구역별 결과를 합치고, alert() 가 초과일 때만 문구를, info() 가 정보 줄을 만든다.
- 나머지 묶음에 구름 낀 묶음이 섞이므로 묶음별 값을 문턱과 하나씩 비교하지 않고 최대 묶음 하나만 지목한다.
- 원인 구분을 더 해 보려고 "그 묶음을 뺀 위 방향에 대한 나머지 묶음의 카메라 x 축 벗어남" 을 점수로 시험했으나 모든 묶음에서 1e-5° 수준이라 구분되지 않았다(묶음마다 방위가 한 방향뿐이면 구름이 위 방향 기울기로 흡수된다). 채택하지 않았다.
- 시험: align 시험(구름 0/2°, 20 시드)에서 문구에 최대 묶음 카메라 이름·값·차이가 들어가는지, 구름 없을 때 알림이 없는지. 통합 시험에서 구름 없는 장면의 issues 에 교차 검사 줄이 없고 events 에 있는지, 문구 단위 시험.

## 남은 문제
- 방위가 묶음마다 한 방향뿐인 배치에서는 세 묶음의 어긋남이 거의 같아 원인 카메라를 어긋남 값만으로 확정할 수 없다. 방위가 섞인 비행이나 묶음 자기 위 방향 갈래가 되는 자료가 필요하다.
- 합성 장면 생성기에 기체별 구름 옵션이 없어 파이프라인 전체 실행의 구름 2° 장면은 아직 없다(회전 수준 시험만).
