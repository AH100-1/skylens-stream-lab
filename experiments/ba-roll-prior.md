# BA 카메라 롤 사전항 (ba-roll-prior)

## 결론

- 정밀 BA 에 카메라 x 축 수평(롤 0) 사전항을 넣었다(GPS/ENU 좌표계에서 x 축의 위 방향 성분을 σ 로 나눈 이차 벌점). 합성 편대 카메라는 `look_rotation` 이 x = d × z 로 만들어 롤이 정확히 0 이라(참값 x 축 수평 위반 0.000°) 가정이 맞다.
- 목표(두 시드 모두 구역별 기울기 ≤ 0.5°)는 못 맞췄다. 시드 1 은 구역 0 이 2.12° → 0.49°(σ 1°)로 들지만 구역 1 은 0.83° → 0.77° 로 거의 그대로다. 시드 2 구역 0 은 1.23° → 1.67°(σ 3°) / 1.91°(σ 1°) 로 오히려 나빠진다.
- 시드 2 구역 0 은 롤 사전항을 걸수록 x 축 수평 위반(출력 포즈)은 줄지 않고(0.73° → 1.13° → 1.33°) 기울기가 커진다. 포즈가 x 축 수평 제약과 사진 관측 사이에서 다른 방향으로 휘는 것으로 보이며, 이 사전항만으로는 구역 안 휘어짐이 안 풀린다.
- 재투영 잔차는 변화 없음(중앙 0.122~0.124 px, 95% 0.555~0.568 px). 중심 오차는 시드 1 에서 소폭 개선, 시드 2 구역 0 에서 σ 1° 일 때 악화(0.50 → 0.64 m). 따라서 기본은 끈 채(`BaRefine::roll_sigma_deg = 0`)로 둔다. 기본값을 바꾸지 않았으므로 pipeline_e2e / pipeline_arrival 은 돌리지 않았다.

## 방법

- `ba::PositionPrior` 에 `roll_sigma`(라디안, 0 이하 = 끔)·`roll_up`(기본 +z)을 추가했다. 카메라마다 잔차 g = e_xᵀ R u / σ (R 은 세계→카메라 회전, 곧 카메라 x 축의 위 성분의 사인), 왼쪽 섭동에서 ∂g/∂ω = (R u) × e_x / σ. 비용 ½g², 정규방정식 카메라 회전 블록에 JᵀJ 와 Jᵀg 를 더한다. 유한차분 시험(`roll_prior_jacobian_matches_finite_difference`)으로 야코비안을 확인했다.
- 설정은 `BaRefine::roll_sigma_deg`(기본 0), `run_ba_with` 에서 위치 사전항에 실어 보낸다. BA 좌표계는 GPS 사전항이 고정하는 ENU 계라 u = +z 로 둔다.
- 측정: `pose_accuracy.rs::measure_roll_prior`(환경변수 `ROLL_SEEDS`, `ROLL_DEGS`, `--ignored --nocapture`)와 목표 단언 `pose_roll_prior_tilt_goal`(`#[ignore]`). `two_region` 이 재투영 잔차 분포도 찍는다. 4 코어 측정 기계에서 다른 작업과 나눠 쓰며 시드별 프로세스 둘을 동시에 돌렸고 한 실행에 8~10 분 걸렸다.

## 남은 문제

- 시드 2 구역 0 의 기울기가 롤 사전항으로 악화되는 이유를 못 가렸다. 사전항이 구역 내부 휘어짐 대신 구역 전체 회전을 밀고 있는 것으로 보인다(위 방향 사전항 기울기 1.26° → 1.69° 로 같이 커짐). 구역 BA 에 GPS 외 수직 제약(고도 σ 분리 등)이나 카메라 간 상대 포즈 강성을 따로 봐야 한다.
- σ 0.3° 와 그 이하, 반복 수 변화는 못 쟀다. 시드는 1·2 둘뿐이다.
