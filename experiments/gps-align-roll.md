# 정밀 모델 GPS 정렬의 비행 축 둘레 회전 (롤)

## 결론

- 시드 4·5 구역2 의 약 13° 기울기는 정밀 BA 가 아니라 BA 뒤 GPS 닮음 정렬(`gps_align_refined`)에서 생긴다. 시드 4 구역2 는 BA 뒤 0.84° 였다가 정렬 뒤 12.74° 가 된다.
  GPS 중심이 거의 한 직선(퍼짐 표준편차 22.9 / 3.3 / 1.35 m)이라 직선 둘레 회전이 GPS 로 정해지지 않는다.
- 첫 시도(정렬 전 모델의 연직을 그대로 유지)는 시드 5 에서 오히려 나빠졌다: 구역별 연직 기울기 중앙값 16.9 / 9.6 / 3.2° (기준 브랜치는 회전 오차 1.195 / 4.834 / 13.457°).
  정렬 전 모델 좌표계의 z 는 연직이 아니었다. 이 규칙은 폐기했다.
- 두 번째 시도: 거의 직선인 경우에만 초기 정렬과 같은 규칙(카메라 광축 높이 분산 최소)으로 비행 축 둘레 회전을 다시 고른다. 시드 5 는
  구역별 회전 평균 오차 0.571 / 1.162 / 0.492°, 연직 기울기 중앙값 0.479 / 0.821 / 0.291° 로 내려갔다(기준 1.195 / 4.834 / 13.457°). 시드 4 도 회전 평균 오차 0.947 / 0.509 / 1.264°, 연직 기울기 중앙값 1.013 / 0.368 / 1.989° 로 13° 기울기가 사라졌다(기준 2.296 / 2.919 / 13.843°). verify 는 시간이 모자라 재지 못했다.
- 문턱 0.25 는 직선 판정이 약하다: 시드 5 구역0 의 둘째/첫째 비 0.129 도 직선으로 잡혀 정상 구역까지 규칙을 건드린다. 시드 4 불량 구역2 의 비는 0.144 라 비로는 구분되지 않는다.

## 방법

- `gps_align_refined` 에서 강건 닮음 변환을 구한 뒤, 정상 대응 GPS 중심 공분산의 둘째/첫째 표준편차 비가 0.25 미만이면 `roll_by_level_spread` 로 비행 축(GPS 첫 주성분) 둘레 회전만 바꾸고
  이동은 정상 대응 무게중심으로 다시 맞춘다. 비행 축이 연직에 가까우면 손대지 않는다. 직선이 아니면 입력 그대로.
- 단위 시험 두 개: 거의 직선 GPS + 13° 기울인 변환 → 정렬 뒤 연직 기울기 1° 미만, 점들이 퍼진 경우 변환이 비트 단위로 같음.
- 시드별 판정표를 찍는 무시 시험 `seed_verify` 를 추가했다. 기울기·회전 오차는 기존 `default_tilt` 로 쟀다.
- 시험: `cargo test --release -p skylens-core --lib pipeline` 은 첫 시도 때 돌렸고(시험 12개 통과, 새 시험 하나는 시험 쪽 오류로 실패 → 고침), 두 번째 규칙에서는 새 시험 `collinear` 만 다시 돌렸다.
  `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings` 통과. 전체 시험은 돌리지 않았다.

## 남은 문제

- 최종 규칙의 시드 1·3·2 측정과 모든 시드의 verify 측정이 없다. 먼저 이것을 재야 한다.
- 직선 판정 문턱을 비 하나로 잡으면 정상 구역이 섞인다. 롤이 정말 정해지지 않는지는 GPS 퍼짐뿐 아니라 정렬 잔차나 롤 변화에 대한 목적함수 민감도로 판단하는 편이 낫다.
- 정렬 전 모델의 연직이 무엇인지(초기 정렬 규칙이 남기는 롤)를 따로 봐야 한다.
