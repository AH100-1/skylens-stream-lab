# JSON 해석기 이스케이프와 포즈 파일 쓰기 보강 (F-394·F-389·F-388)

## 결론
손으로 짠 JSON 해석기가 `\b`·`\f`·서로게이트 쌍을 바른 글자로 읽고, 짝 없는 서로게이트와 알 수 없는 이스케이프는 오류로 돌려준다. 포즈 파일 쓰기는 내부 파라미터(fx·fy·cx·cy)가 비유한이면 파일을 만들지 않고 오류를 돌려주며, 건너뛴 비유한 포즈의 개수를 반환값과 파일 필드(`skipped_non_finite`)로 남긴다. 호출부(`pipeline.rs`)의 구역별 경고·통계 개수와 파이프라인 시험은 맡은 파일 밖이라 하지 않았다.

## 수치 표
| 시험 | 입력 | 기준 | 결과 |
|---|---|---|---|
| `\b`·`\f` | `"\b"`, `"\f"` | U+0008, U+000C | 통과 |
| 서로게이트 쌍 | `"😀"`, 앞뒤 글자 사이 | U+1F600 한 글자 | 통과 |
| 오류 8종 | `\x` `\a` 짝 없는 높은·낮은 서로게이트, 높은 뒤 비서로게이트, `\u12`, `\u+123` | 모두 오류 | 통과 |
| 비유한 내부 파라미터 | fx=NaN, fy=inf, cx=-inf, cy=NaN | 오류, 파일 없음 | 4/4 통과 |
| 건너뛴 수 | 3개 중 중심 inf 1개 | 반환 1, 파일 필드 1, 읽은 수 + 건너뛴 수 = 3 | 통과 |

## 방법
- `string()` 의 이스케이프 갈래를 `" \ / b f n r t u` 만 받도록 바꾸고 그 밖은 오류. `\u` 는 16진수 4자리만 받고(`+` 불허), 높은 서로게이트(D800–DBFF)는 바로 뒤 `\u` 낮은 서로게이트(DC00–DFFF)와 합쳐 `0x10000 + ((hi-0xD800)<<10) + (lo-0xDC00)`, 짝이 없으면 오류.
- `write_poses_file` 은 쓰기 전에 fx·fy·cx·cy 유한성을 검사. 반환형을 `Result<usize, String>` 으로 바꿔 건너뛴 수를 돌려준다. 기존 호출부는 `?` 만 쓰므로 그대로 컴파일된다.
- F-389 는 '오류' 쪽을 택했다. 머리의 값이 깨지면 포즈 전체가 무의미하고 `null` 로 쓰면 읽기 쪽이 거부하기 때문이다.
- 이전 노트의 표 "기존 시험 5개" 는 기존 3개 + 새 2개였고, `poses_io.rs` 문서 주석의 `\uXXXX` 는 역슬래시 하나로 확인했다.

## 남은 문제
- 호출부 `pipeline.rs:2544·2557` 가 반환 개수를 아직 쓰지 않는다. 구역별 경고, 실행 통계 개수, "포즈 항목 수 + 건너뛴 수 = 등록 사진 수" 구역 파이프라인 시험이 남았다(F-388 의 나머지).
- 내부 파라미터가 비유한이면 호출부의 `?` 때문에 파이프라인이 그 구역에서 오류로 멈춘다. 경고로 낮출지는 호출부 쪽 결정.
- 같은 `Json` 해석기는 숫자 문법·중복 키·제어 문자 원문 검사는 하지 않는다(이번 범위 밖).
