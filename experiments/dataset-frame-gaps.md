# dataset-frame-gaps: 세 카메라가 모두 빠진 프레임을 건너뜀으로 센다

## 결론
- STRIDE 후보를 "사진이 있는 프레임 중 격자 위인 것"에서 "f0..=f_last 의 격자 f0 + k·STRIDE 전부"로 바꿨다.
  사진이 하나도 없는 격자 프레임은 개수를 산술(k 의 차)로 세어 `skipped`(세 카메라 모두 missing)와
  연속 검사에 넣는다. 프레임 번호가 4000000000 이어도 공백을 한 칸씩 돌지 않는다.
- 허용(`max_skip_run`)을 넘는 연속은 어차피 오류이므로 목록으로 풀어 쓰지 않는다(메모리 보호).
- 합성 장면 기본 경로의 위치 수는 그대로다(통합 시험 통과).

## 수치 표
| 경우 | 이전 | 이후 |
|---|---|---|
| 0..39 에서 6..30 을 세 카메라 모두 삭제 | 위치 프레임 [0,3,33,36,39], skipped 없음, Ok | SkipRun{first 6, last 30, count 9, limit 2} |
| 프레임 6 만 세 카메라 모두 삭제 | skipped 없음 | skipped == [6](missing 세 카메라), 위치 13곳, CLI `skipped 1 (frames 6)` |
| 프레임 0 과 4000000000 (STRIDE 1) | 위치 2곳 | SkipRun{first 1, last 3999999999, count 3999999999}, 1 초 미만 |
| 같은 입력 (STRIDE 3) | 위치 1곳 | SkipRun{first 3, last 3999999999, count 1333333333}, 1 초 미만 |
| 33..39 모두 없음 (f_last = 32) | 위치 11곳 | 위치 11곳, skipped 없음(격자 끝 30) |

시험: dataset 단위 26개 통과, dataset_synth 2개 통과.

## 방법
- 있는 격자 프레임(k = (f−f0)/STRIDE)을 순서대로 보며 직전 k 와의 차로 빠진 격자 수를 구하고, 진행 중인
  연속에 더한다. 마지막에 f_last 까지의 끝 공백도 같은 방식으로 더한 뒤 검사한다.
- 일부 카메라만 빠진 프레임과 한 연속으로 이어진다(앞뒤 끝 포함은 기존 규칙 그대로).

## 남은 문제
- `max_skip_run` 을 아주 크게 주면 허용 안의 빠진 격자를 모두 `skipped` 에 풀어 쓰므로 목록이 길어진다.
  구간 표현은 넣지 않았다.
- 끝 프레임이 격자 위가 아니면 그 뒤 프레임은 후보가 아니다(위 표 마지막 줄).
