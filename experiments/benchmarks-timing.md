# benchmarks-timing — 인자 없는 bench 를 수 분 규모로, 240장 재측정 (T14, F-132·F-149·F-128·F-040)

## 결론
- **F-132: 인자 없는 `cargo bench --bench pipeline` 이 20 s 에 끝났다**(4 코어 측정 기계, 부하 평균 15.4→16.9, 다른 빌드와 동시).
  기본값을 위치 8(24장)·480×270 은 그대로 두고 반복 3→1, 짝 상한 0(전부 231)→40 으로 줄였다. `--full` 은 짝 상한을 0(전부)으로
  되돌리고 반복 3 이다. 표 합계(중앙) 19.1 s 중 렌더 10.5 s·E RANSAC 3.6 s·번들 조정 1.9 s·검출 1.8 s.
  같은 부하대의 이전 기본값 실행(benchmarks-args, 부하 평균 26~38) 471.6 s 와 비교하면 반복 3배·짝 5.8배 감소가 대부분을 설명한다.
- **F-149: 주석은 `benches/pipeline.rs` 를 가리킨다**(`grep -rn bench_stages crates` 결과 없음). `회전 평균(검증 결과)` 줄 값:
  기본 실행 17 간선·반환 시점 6/24·2° 초과 0/17·정렬 오차 중앙 0.021°, 240장(320×180) 실행 1556 간선·반환 시점 80/240·
  2° 초과 36/1556(2.3%)·정렬 오차 중앙 0.198°. 부하 평균 < 2 단독 측정은 이번에도 할 수 없었다(부하 평균 15~32).
- **F-128: 현재 main(50fce8a) 장면으로 240장 320×180 을 다시 쟀다.** 검증 통과 짝 1556/3663(42%) — 이전 노트 1958/3663(53%)과 다르다.
  렌더 제외 합계 330.1 s 중 **E RANSAC 225.2 s(68%)**, 번들 조정 67.8 s(21%), F RANSAC 17.0 s, 검출 11.4 s, 비율 매칭 6.6 s.
  두 시점 검증(E + 자세) 227.1 s. 부하 평균 16.7→25.3 에서 잰 값이므로 절대 시간이 아니라 단계 비율로만 쓴다.
  검출 해시: main 에는 해시 시험이 없다(F-130 대로 features.rs 쪽 시험은 pixel-convention 병합 대기). 이번에 해시를 새로 재지 않았다.
- **F-040: 미착수.** `--full` 에 번들 조정 실제 규모(카메라 240·트랙 10만)를 넣는 일과 구간 분해는 남았다(현재 `--mode ba-scale` 로만).

## 방법
- 제품 작업 트리에서 `CARGO_BUILD_JOBS=2`, 전용 빌드 폴더. 시작·끝 부하 평균은 `uptime` 1분 값.
- A 와 B 는 같은 바이너리. B 는 같은 기계에서 다른 묶음 빌드와 이 브랜치의 clippy·시험 빌드가 함께 돈 동안 쟀다.
- 시험: `cargo fmt --all --check` 통과, `cargo clippy --all-targets -- -D warnings` 통과. `cargo test --release` 는
  lib 의 `verify::tests::nn_median_many_identical_points_is_fast_and_exact`(1.0 s 시간 단언)가 부하 평균 32 에서 실패했고,
  단독 재실행(부하 평균 31)에서 0.60 s 로 통과했다. 전체 결과는 아래 남은 문제.

## 남은 문제
- 부하 평균 < 2 단독 실행 값(F-149·F-128 확인 기준)이 없다.
