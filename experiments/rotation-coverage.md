# 회전 평균 시점 커버리지 (rotation-coverage)

## 결론
- F-209 의 "75/231" 은 평면 후보 순위(#30)에서 짝을 거부해서 생긴 손실이 아니다. 순위 단계(`plane_facing`)는 후보 순서만 바꾸고 짝을 버리지 않으며, 지금 main(1578181, 짝 일정 #44 포함)에서도 같은 값이 나온다. 잃은 26짝은 원래 겹침이 없는 다른 카메라 짝이 옛 트리에서 우연히 통과했던 것이다(옛 101 의 회전 오차 중앙 69° 와 2° 초과 간선 27개가 그 흔적). 그 우연 통과는 997437e 의 정상 수 유의성 검사로 막혔다.
- 기본 bench(위치 8곳, 24장)에서는 다른 카메라 짝이 구조적으로 겹치지 않는다. 같은 위치 F–R·F–L 겹침 0%, 위치 차 +12 이상부터 겹친다(연구 노트 formation-pairs). 위치가 0..7 뿐이면 겹치는 다른 카메라 짝이 없으므로 정직한 간선만으로는 24/24 가 될 수 없다. 현재 bench 는 같은 카메라 75/75 성공, 다른 카메라 0/156 성공, 연결 성분 3(F·R·L)이다. 그래서 F-209 의 "같은 명령에서 24/24" 기준은 이 규모에서 충족 불가이며, 반환 8/24 는 F 카메라 한 대 분량이다.
- 대신 겹침이 있는 위치로 시점을 고른 편대 장면에서는 기준이 충족된다: 시점 16개 모두 반환, 통과 간선 2° 초과 2/51(3.9%), 정렬 오차 중앙 0.141°. 이를 단언하는 시험을 넣었다(`formation_verified_edges_average_all_views`).
- F-249: 짝 상한이 걸린 40 짝과 231 짝 전부 비교는 이 회차에서 40 판을 새로 재지 못했다(아래 남은 문제). bench 사용법 표에 회전 평균 확인 때는 `--max-pairs 0` 을 명시하도록 적었다.

## 수치 표
현재 main 1578181, `cargo bench --bench pipeline -- --max-pairs 0 --repeat 1`(24장 480×270, 짝 231, 4 코어 측정 기계, 부하 평균 약 15~20이라 시간은 참고용).

| 항목 | 값 |
|---|---|
| E RANSAC 성공(전체) | 75/231 |
| 같은 카메라 짝 | 75/75 |
| 다른 카메라 짝 | 0/156 |
| 두 시점 자세 성공 | 75/231 |
| 회전 평균 반환 시점 | 8/24 (연결 성분 3) |
| 통과 간선 2° 초과 | 1/75 (1.3%) |
| 정렬 오차 중앙 | 0.031° |

편대 장면 시험(시드 1, 480×270, F 위치 0·4·8·12, R·L 위치 32..52 4칸 간격, 카메라 간 짝 일정 +32..=+40 4칸 간격, 부하 평균 약 15~20):

| 항목 | 값 |
|---|---|
| 일정 짝 | 51 |
| E 통과 | 51 |
| 통과 간선 2° 초과 | 2/51 (3.9%): F4–L36, F4–R44 가 각각 3.01° |
| 반환 시점 | 16/16 |
| 정렬 오차 중앙 | 0.141° |

짝 종류별 차이 표(옛 트리 대 새 트리 26짝)는 옛 트리를 다시 빌드해 짝별로 덤프하지 못했다. 위 결론은 현재 트리의 종류별 성공 수(같은 카메라 75/75, 다른 카메라 0/156)와 옛 트리의 오차 분포에서 추론한 것이다.

## 방법
- bench 의 E RANSAC 줄에 같은 카메라/다른 카메라 성공 수, 회전 평균 줄에 통과 간선 그래프의 연결 성분 수를 덧붙였다.
- 시험은 편대 장면에서 시점을 고르고 `scheduled_pairs` 로 짝을 만든 뒤 비율 매칭(0.8, 상호) → `ransac_essential` → `recover_pose` → `average_rotations`. 정답 상대 회전 R_j R_iᵀ 와 2° 비교, `aligned_errors` 중앙을 단언한다.
- 시점 선택: F 3개·R/L 5개로 먼저 돌리면 2° 초과 2/37(5.4%)로 기준(5% 미만)에 못 미쳐, F 위치와 R·L 위치를 하나씩 늘린 16시점으로 정했다. 같은 두 간선이 3.01° 라 표본이 작을 때의 비율 문제이며, 간선 자체는 카메라 간 오차 문제(F-251)에 속한다.

## 남은 문제
- 기본 bench 규모(8곳)에서는 24/24 가 불가능하다. 24시점 전부를 잇는 확인 명령이 필요하면 겹침이 있는 위치를 포함하는 규모(위치 약 20 이상)나 편대 시점 선택을 bench 에 넣어야 하는데, 이번에는 bench 짝 생성을 SPEC 전체 짝 그대로 두었다.
- 카메라 간 간선 중 3° 근처 오차가 남아 있다(F-251). 간선 수가 적으면 비율이 5% 를 넘나든다.
- `--max-pairs 40` 판의 같은 줄을 이번 회차에서 재지 못했다.
- 옛 트리와의 짝별 차이 표 미완.
