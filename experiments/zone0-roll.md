# 구역 0 주 모델 롤: 정밀 시작점의 롤 규칙

## 결론

- 구역 0 의 14.6° 는 롤 후보 선택이 아니라 그 앞, 정밀 BA 시작점을 만드는 단계에서 생겼다. 정밀 시작점(`legacy_roll`)은
  비행 축 둘레 회전을 2° 간격 탐색(시선 연직 성분 평균 최소)으로 골라 구역 0 에서 이미 17° 틀렸고, BA 는 이를 거의 못 고친다.
  초벌 쪽(광축 높이 분산 최소 롤)은 같은 구역에서 1.5° 였다.
- 이전 코드에서 구역 0 은 GPS 해(14.7°)가 뽑혔고 퍼짐 해는 4.5° 였다. 당시 두 잔차 값은 기록하지 못했다(잔차 출력을 시험 출력에 넣기 전).
  바꾼 뒤에는 세 구역 모두 두 잔차가 0.1 % 안팎(예: 2.463 / 2.465)이라 롤을 가르지 못하고 퍼짐 해가 뽑힌다.
- 정밀 시작점(구역 시작, 다시 등록한 전체 목록)을 초벌과 같은 높이 분산 롤로 바꾸니 시드 5 구역 0 정면·오른쪽이
  14.74°→2.38°, 왼쪽 22.42°→1.59°. preview_vs_refined 통과(최근접 4.016→1.296 m, 높이 차 5.218→1.317 m). verify 5/7→6/7.
- 목표 미달: 구역 0 정면·오른쪽 2.38°(목표 2° 이하)가 남았고, 구역 1 은 2.47°→4.39° 로 나빠졌다. registered 80/81 은 그대로다.
  시드 1 은 7/7 유지. 시드 2~4 는 시간이 모자라 재지 않았다.

## 방법

1. 시험 보조에 단계별 정답 비교를 넣었다: 진단 출력의 단계 자세를 정답과 비교해 모든 카메라 공통 회전(척도 평균)과 그것을 뺀 나머지를
   낸다. 오차는 사진끼리 어긋난 것이 아니라 거의 전부 모델 전체의 기울기다(나머지 0.1° 안팎, 구역 1 에서 0.3°).
2. `gps_align_refined` 에서 두 롤 후보의 정렬 뒤 자세를 같은 방식으로 낸다.
3. 정밀 시작점과 다시 등록한 전체 목록의 초기 모델 롤 규칙을 `legacy_roll: true` 에서 false 로 바꿨다(코드 두 줄).
4. 시험 `zone_rotation_error_limit`(실행 시 무시 표시): 시드를 돌려 구역별 최종 회전 오차 중앙값이 구역 0 은 3°, 나머지 4.5° 이하.

## 남은 문제

- 구역 1 이 나빠졌다(2.5°→4.4°). 정밀 BA 직후는 3.3° 이고 퍼짐 롤이 4.4° 로 키운다: 높이 분산 최소 롤은 지형 기복에 치우친다.
  구역마다 오차가 1.6~4.4° 로 흔들려 롤 규칙 자체가 약하다. 정답 없이 2° 안을 보장하려면 롤 후보의 신뢰 판정이나
  L 성분을 붙인 뒤 재선택이 필요한데, 시간 부족으로 검토하지 못했다.
- 구역 0 정면·오른쪽 2.38° 가 2° 목표 미달.
- registered 80/81 한 장 미등록은 원인 미확인. 시드 2~4 재측정 안 함.

## F-372·F-374 대응

### 결론

- 정밀 재정렬 기록이 3 개(0→1 0.145 m, 1→2 0.054 m, 0→2 via 1 0.145 m)가 된 원인은 롤 규칙이 아니라 분리 성분 합치기(`merge_detached`)다. 합치기를 끄면 정밀 구역 등록이 10/30·12/36·8/24 로 줄어 기록이 1 개(1→2, 0.028 m)뿐이고, 켜면 30/30·36/36·24/24 로 모두 등록되어 이웃 구역 짝이 모두 맞춰진다. 구역 0 과 2 는 겹치지 않아 구역 1 을 거친 연쇄 기록(0→2 via 1)이 하나 더 생긴다. 의도한 결과다.
- 시작 롤을 `legacy_roll: true` 로 되돌려도 기록은 같은 3 개(0.145 / 0.055 / 0.145 m)라 롤은 원인이 아니다.
- 시험은 개수 대신 성질로 확인한다: 기록 1 개 이상, 구역 n 개일 때 n(n−1)/2 이하, 잔차 모두 1 m 미만.
- F-374 네 항목 모두 반영했다(미사용 인자 제거, 불필요한 정렬 제거, 롤 닫힌 식, ICP 겹침 잔차 조건).

시험(4 코어 측정 기계, `cargo test --release -j 2`, 전체 실행 약 20 분 이상):

- skylens-core 단위 시험: 345 통과, 0 실패, 31 무시, 884.33 s. `detached_tests` 5 개 통과(새 시험 2 개 포함, 0.43 s).

### 방법

1. 합치기 끄기와 시작 롤 되돌리기를 각각 로컬에서만 바꿔 같은 시험을 돌려 보고서의 재정렬·정밀 구역 기록을 비교했다(커밋에는 넣지 않음).
2. 비행 축 둘레 롤을 0.5° 간격 720 단계 탐색에서 닫힌 식으로 바꿨다: 두 법선에서 축 성분을 뺀 벡터 사이의 부호 있는 각. 단위 시험에서 탐색 결과와 비교해 각 차가 0.25°(탐색 간격의 절반) 이내이고 닫힌 식의 정렬 각이 탐색보다 나쁘지 않음을 확인했다.
3. `merge_detached_components` 의 쓰이지 않던 `keep_edge` 인자를 뺐고, `attach_detached` 의 개수 확인에만 쓰이던 첫 잔차 계산을 지웠다(이어지는 반복에서 같은 문턱을 이미 검사한다).
4. ICP 보정은 GPS 정상 대응 수에 더해, 점 겹침 잔차(최근접 거리 상한 3 m 의 평균)가 늘지 않을 때만 받아들인다. 시험: 이미 겹친 점(잔차 0)에 한쪽으로 당기는 앵커를 주면 ICP 가 잔차 0.288 m 를 만들어 거절된다.

### 남은 문제

- 전체 `cargo test --release` 가 마감 시각에 끝나지 않아 cli 시험 일부의 전체 실행 결과가 없다(`helper_latency` 는 단독으로 통과).
- ICP 거절 시험은 인위적인 앵커로 만든 경우다. 실제 장면에서 거절이 얼마나 일어나는지는 재지 않았다.
