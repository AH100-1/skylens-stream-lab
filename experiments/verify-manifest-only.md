# verify: SPEC §2 출력만으로 항목 1~3 판정

## 결론
- 등록 사진(1)과 구역 사진 수(2)는 `preview/`·`refined/` 파일 이름의 위치 범위 `pos{lo}-{hi}` 에서 계산해 판정한다. `report.json` 이 있으면 그 값도 맞아야 통과하는 추가 검사로만 쓴다.
- 재투영 오차(3)는 SPEC §2 의 어떤 파일에서도 계산할 수 없다. `report.json` 이 없으면 FAIL 이 아니라 "판정 불가"(종료 코드 2)로 남는다. 이 항목은 출력 형식(SPEC)에 값을 올리지 않는 한 해결되지 않는다.
- `report.json` 을 지운 출력에서 항목 1·2·4~7 의 판정은 지우기 전과 같다(합성 장면 출력 3가지로 확인).

## 수치 표 (합성 장면: 구역 pos0-14, pos10-26)
| 항목 | report.json 있음 | report.json 없음 |
|---|---|---|
| 1 등록 사진 | PASS (초벌 240/240, 정밀 240/240 + 이름 계산 78/78) | PASS (초벌 78/78, 정밀 78/78) |
| 2 구역 사진 수 | PASS | PASS (구역 0: 14→42장, 구역 1: 16→48장) |
| 3 재투영 | PASS (0.700 px) | 판정 불가 |
| 4 초벌 정렬 | PASS | PASS |
| 5 초벌↔정밀 | PASS (1.990 m) | PASS (1.990 m) |
| 6 이웃 겹침 | PASS (0.290 m) | PASS (0.290 m) |
| 7 스냅샷 | PASS | PASS |
| 종료 코드 | 0 | 2 |

정밀 구역 이름을 pos20-26 으로 바꿔 위치 14..20 에 빈틈을 내면 report.json 없이도 1·2 가 FAIL(정밀 60/78), 종료 코드 1.

## 방법
- 등록: 초벌·정밀 각각 이름 범위 합집합이 0..마지막 위치를 빈틈없이 덮는지 계산, 위치 하나 = 사진 3장.
- 구역 사진 수: 구역마다 초벌·정밀 범위 동일, 0 에서 시작, 이웃과 겹쳐 이어짐을 확인하고 3 × 위치 수를 표시.
- report.json 이 있으면 기존 값 검사를 더해 둘 다 맞아야 통과. 깨진 파일은 FAIL.

## 남은 문제
- 1·2 는 "구역 파일이 위치를 덮는다"는 대리 지표이고, 실제 등록 실패 사진 수나 구역 밀집에 쓴 사진 수는 출력에 없다.
- 3 은 SPEC §2 에 재투영 값이 올라가기 전에는 판정 불가.

## 개정 1 (검토 지적 F-402~F-404 반영)
### 결론
- 파일 이름만으로는 입력 위치 수 N 을 알 수 없다. 끝 구역 이름이 줄거나 파일이 사라져도 남은 이름은 빈틈 없이 이어지기 때문이다. 그래서 항목 1 은 `report.json` 이 없으면 빈틈이 있을 때만 FAIL, 빈틈이 없으면 "판정 불가"(종료 코드 2)로 바꿨다. 이전 표의 "report.json 없음 → 1번 PASS" 는 취소한다.
- (개정 2 로 바뀜) `report.json` 이 있으면 report 의 구역 목록(번호·positions)이 기준이다. 출력 구역 번호 집합과 `positions == hi−lo` 가 같아야 하고(빠진 구역·잘린 범위는 FAIL) 등록 수 == total 이어야 한다. total 은 입력 위치 수 기준이라 이름 끝 위치와 비교하지 않고 구역 수 == ⌈N/SPAN⌉ 도 요구하지 않는다. 항목 1·2 모두 이 대조를 쓴다.
- 항목 2 는 "위치 범위 구조 검사(사진 수는 출력에 없음)" 로 문구를 바꾸고, 구역 0·1 에서 SPAN = (구역 0 끝 + 구역 1 시작)/2, OVL = (구역 0 끝 − 구역 1 시작)/2 를 추정해 구역 k 가 [kS−O, kS+S+O) 인지, 끝 구역은 hi 가 (kS+O, kS+S+O] 안인지 본다. 구역 번호는 0..K 연속이어야 한다.
- 같은 구역 번호 파일 중복과 이름 해석 실패는 FAIL 사유다.

### 수치 표 (합성 이름: N=80, SPAN 12, OVL 2, 구역 7개)
| 경우 | 항목 1 | 항목 2 |
|---|---|---|
| 정상, report 없음 | 판정 불가 | PASS |
| 정상, report 240/240 | PASS | PASS |
| 끝 구역 pos10-26 → pos10-20 (2구역 예), report 없음 | 판정 불가 | PASS(구조는 가능한 범위) |
| 같은 출력, report 78/78 | FAIL (끝 위치는 20, 구역 수 2 ≠ ⌈26/12⌉ = 3) | - |
| 끝 구역 두 파일 삭제, report 240/240 | FAIL (3×80 인데 끝 위치 74) | FAIL (report 에만 있는 구역 6) |
| 겹침 1칸 [0,14)·[13,26) | - | FAIL |
| 번호 0·2 만 | - | FAIL (건너뜀 [1]) |
| 경계 어긋남(구역 2 시작 23, 끝 37; 끝 구역 hi 52·36) | - | FAIL 4건 |
| [0,14)·[0,26), [0,14)·[0,14), hi<lo, 한쪽 폴더만 빈 경우 | - | FAIL |
| refined_01_pos10-26 과 refined_01_pos20-26 | FAIL | FAIL (파일 중복) |

변이 확인: 구역 시작·끝 경계 비교(`a.0 == lo_exp`)를 `true` 로 바꾸면 `region_structure_follows_span_ovl_rule` 이 실패한다. 이전 코드의 `a.0 > plo` 조건은 규칙 비교로 대체되어 사라졌고, 같은 종류의 어긋남([0,14)·[0,26) 등)을 같은 시험이 막는다.

### 방법
이름만 있는 빈 PLY 로 출력 폴더를 만들어 `verify_dir` 의 항목 1·2 를 직접 보는 시험 8건 추가(코어 verify 시험 19건 통과, 4 코어 측정 기계).

### 남은 문제
- 구역이 하나뿐이면 SPAN·OVL 을 추정할 수 없어 구조 검사는 시작 위치 0 만 본다.

## 개정 2 (조정 반영)
- 개정 1 의 total==3×끝 위치, 구역 수==⌈N/SPAN⌉ 조건은 뺐다. 기존 합성 출력(pos0-14·pos10-26, total 240)은 출력 구역이 전체 위치를 다 덮지 않으므로 정상이다.
- F-402 두 재현: (a) 끝 구역 pos10-20 + report(구역 1 positions 16) → 항목 1·2 FAIL(positions 16 ≠ 20−10); (b) 끝 구역 파일 삭제 + report 240/240 → 항목 1·2 FAIL(report 에만 있는 구역 6). report 없이는 둘 다 항목 1 판정 불가.
- 새 규칙에서도 기존 정상 출력(구역 0·1: SPAN 12, OVL 2)은 구조 검사를 통과한다.
- 시험 수: 코어 `--lib verify` 19건, cli `--test verify` 26건 모두 통과. cli 시험은 보고 없는 출력의 항목 1 기대만 '판정 불가'로 바꾸고(`spec_outputs_only_decides_from_files`: 5/7 통과, 판정 불가 2개), `report_json_removal_keeps_verdicts` 의 비교 항목에서 항목 1 을 뺐다(같은 이유).
