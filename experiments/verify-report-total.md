# verify 항목 1 의 report total 대조와 등록 진단 시험 보강

## 결론
- 항목 1(등록 사진)은 report 가 있으면 `registered.total == 3 × 출력 이름의 끝 위치`도 요구한다. 실제 실행은 total = 3 × 위치 수, 끝 구역 hi = 위치 수이므로 끝 구역이 목록과 파일에서 함께 빠진 report 를 PASS 로 두지 않는다. 시험 고정물을 total 78(위치 26)로 맞췄고, total 240(위치 80)에 이름 끝 26 인 경우는 FAIL 로 단언한다.
- 시드 5 진단 시험은 `| registered |` 줄에서 등록 수를 못 읽으면 실패하고, `REG_MIN` 이 없을 때도 등록 1장 이상을 요구한다(기본값 0 의 항상 참 단언 제거). 줄 해석은 별도 함수 `parse_registered` 로 떼어 무거운 실행 없이 단위 시험으로 검사한다.
- up_cross 가 실패할 때도 실패 문구 끝에 '경고: 구역 k 미측정' 이 붙는다. 진단 시험(up_cross_seeds)의 최종 실패 문구에도 미측정 구역이 남는다.
- 아래 시드 5 재측정은 하지 않았다(미측정). 단위 시험과 verify 시험만 돌렸다.

## 방법
- verify.rs `registered_item`: report 가 읽히고 total 이 숫자면 `3×max_hi` 와 비교, 다르면 이유를 문구에 넣는다. 시험 `registered_report_total_is_input_based` 수정.
- check_up_cross 실패 분기: 미측정 구역 목록을 덧붙임. 시험은 구역 0 null·구역 1 10.5° 에서 두 정보가 모두 나오는지 단언.
- 진단 시험 두 파일에 단위 시험 추가(등록 줄 해석 6가지 경우, 실패 문구 구성, 전부 null 구역 해석).

## 구역 0 '그 밖 13장'의 출처 (F-452)
구역 0 은 앞 구역이 없어 앞쪽 도우미가 없다. 13장은 뒤쪽 도우미 슬롯이다: gid 3p+2(카메라 2), 시점 p = 14~26. 구역 1 의 1장은 시점 26 의 카메라 2(gid 80)다. 코드의 도우미 선택 규칙으로 계산한 값이며 재실행으로 확인하지는 않았다. 앞서 쓴 노트(seed5-reg-diag)의 같은 행도 이 값으로 고쳤다.

## 남은 문제
- verify 의 두 보강은 단위 시험으로만 확인. 시드 5 진단 재실행은 미측정.
- 기존 시드 5 의 카메라 2 등록 누락 원인(회전 평균 가지치기)은 이번 범위 밖.
