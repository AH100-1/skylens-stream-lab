# P12 dataset-io — 입력 데이터셋 읽기와 `run` 뼈대

## 결론
채택 제안. SPEC §1 입력(`images/cam{F,R,L}/cam{F,R,L}_{번호:04}.jpg`, `gps.txt`)을 읽어
STRIDE 로 프레임을 고르고, 세 카메라가 모두 있는 프레임만 위치 0, 1, … 로 매긴다.
GPS 는 첫 기록을 원점으로 동-북-위(m)로 바꾼다(`geo.rs` 그대로 사용).
SPEC §3.5 구역 분할 `[start−OVL, start+SPAN+OVL) ∩ [0, n)` 을 같은 모듈에 두었고,
80위치·SPAN 12·OVL 2 의 경계가 손 계산과 일치한다.
`skylens-stream run` 은 지금은 위치 수·사진 수·구역 목록을 출력하고 `preview/ refined/ snapshots/` 만 만든다.

## 수치
| 검증 | 손 계산 | 결과 |
|---|---|---|
| 구역 경계 n=80, SPAN 12, OVL 2 | 0..14, 10..26, 22..38, 34..50, 46..62, 58..74, 70..80 (7개) | 일치 |
| 구역 경계 n=13, 12, 2 | 0..13, 10..13 | 일치 |
| 구역 경계 n=10, 4, 0 | 0..4, 4..8, 8..10 | 일치 |
| 프레임 0..9, camR 6 빠짐, STRIDE 3 | 위치 = 프레임 0, 3, 9 (3곳, 사진 9장) | 일치 |
| 같은 자료 STRIDE 1 | 9곳 | 일치 |
| 경도 +9e-5°, 위도 37° 의 동쪽 거리 | 6378137·cos37°·9e-5·π/180 ≈ 8.0 m | ±0.05 m 안 |
| CLI: 프레임 0..39, STRIDE 3, SPAN 5, OVL 1 | 14곳, 42장, 0..6 / 4..11 / 9..14 | 일치 |
| CLI: 프레임 0..9, 기본값 | 4곳, 구역 0..4 | 일치 |
| CLI: STRIDE 4 | 3곳 | 일치 |
| gps.txt 형식 오류(항목 수·수 아님·범위 밖·번호 없음·다른 값 중복) | 해당 줄 번호 | 5경우 모두 일치 |

## 방법
- `crates/core/src/dataset.rs`: `DatasetConfig { stride: 3, span: 12, ovl: 2 }`, `load_dataset(root, cfg)`, `chunk_ranges(n, span, ovl)`, `parse_gps(text)`.
- 프레임 선택: 세 카메라 폴더 중 어디든 있는 가장 작은 번호 f0 부터 f0, f0+STRIDE, … ; 그중 세 장이 다 있는 것만 위치로 쓴다.
- GPS 이름은 끝의 숫자를 프레임 번호로 본다(`camF_0003.jpg`, `0003` 모두 3). 빈 줄과 `#` 줄은 건너뛴다.
- 오류: 폴더·gps.txt 없음(`Missing`), 형식 오류(`GpsFormat{line}`), 고른 위치의 GPS 없음(`GpsMissing{frame}`), STRIDE·SPAN 0(`Config`).
- 시험용 가짜 데이터셋은 임시 폴더에 만들고(단위 시험은 빈 파일, CLI 시험은 8×8 jpg), 끝나면 지운다.

## 남은 문제
- 합성 장면 생성기(`synth`)는 사진을 `images/camF_0000.jpg` 처럼 카메라 폴더 없이 쓴다. SPEC §1 구조와 맞추거나 읽기에서 둘 다 받아야 한다.
- 한 카메라만 빠진 프레임은 조용히 건너뛴다. 건너뛴 수를 출력에 보이면 좋겠다.
- jpg 를 해독하지는 않는다(존재만 확인). 깨진 사진은 다음 단계에서 걸린다.
