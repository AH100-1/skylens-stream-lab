# refine-start-seeds — 정밀 BA 시작점 위치 다듬기 스위치를 잡음 시드별로 재기

## 결론
- 스위치(켬)는 시드 5개 중 3개에서 위 방향 오차가 줄고 2개(시드 3, 4)에서 늘었다. 평균은 1.011 → 0.989 도로 거의 같고 최악은 +0.432 도(시드 3: 2.259 → 2.691)다. **모든 시드에서 나빠지지 않는다는 조건을 못 채우므로 기본값 후보로 올리지 않는다.** 기본값은 바꾸지 않았다.
- 앞선 한 실행의 0.473 → 0.166 도는 시드 1 에서 재현되지 않았다(끔 0.434 → 켬 0.280). 개선은 있으나 크기가 한 실행 값보다 작다.
- 시드 3 은 끔에서도 위 방향 오차 2.26 도, 카메라별 회전 오차 중앙 4~5.5 도로 시작점 문제와 별개로 크게 어긋난 실행이다. 스위치는 이 실행의 회전 오차 중앙을 바꾸지 않았다(소수 셋째 자리까지 같음).
- 켬은 실행 시간이 25~35% 늘었다(약 150 → 180~210 초, 코어를 다른 측정과 나눠 쓴 값이라 거칠다).

## 방법
- 시험 `crates/cli/tests/refine_start_seeds.rs`(`#[ignore]`). 시드별로 장면을 만들어 같은 입력을 스위치 끔/켬으로 `run_pipeline` 한 뒤, 정답과 비교한다. 스위치는 `stage_diag_refined_start`(진단용, 기본 꺼짐)이며 코드는 바꾸지 않았다. 기본 경로는 같은 시험 안에서 기본 장면·`DatasetConfig::default`·`PipelineConfig::default` 로 돌린다(프로세스로 돌리는 `default_path` 와 같은 설정).
- 명령: `RSS_SEEDS=1,2 RSS_DEFAULT=1 cargo test --release -p skylens-stream --test refine_start_seeds -- --ignored --nocapture` (시드 목록은 `RSS_SEEDS`, 기본 경로 시드는 `RSS_DEFAULT`, 빈 값이면 건너뜀). 시드 3·4, 시드 5 는 따로 나눠 돌렸다.

## 남은 문제
- 시드 3 이 끔에서도 2.26 도로 벗어나는 원인과, 켬에서 시드 3·4 가 나빠지는 원인을 못 가렸다. 시드 3 의 회전 오차가 스위치와 무관하게 같은 값이라 시작점 위치가 아니라 회전 쪽 문제일 가능성이 있다.
- 시드 5개는 분포를 말하기에 적다. 기본 경로는 시드 하나뿐이다.
- 시간은 다른 측정과 코어를 나눈 값이라 켬의 비용은 대략치다.
