# 전체 실행 단계별 시간 (합성 240장)

## 결론

- 합성 기본 장면(960×540, 3 카메라 × 80 위치 = 240장)을 `--stride 1 --span 48 --ovl 2` 로 끝까지 돌리면 벽시계 524 초, 최대 상주 메모리 1658 MB. `verify` 는 7/7 통과.
- 가장 큰 단계는 매칭이다. 벽시계로 약 317 초(두 구역 합), 짝 단위 CPU 누적은 비율 검사 423 초 + 5점 RANSAC 824 초. 특징 검출이 117 초, 밀집 깊이가 111 초로 그 다음.
- 이번에는 속도 개선을 넣지 않았다. 측정 내내 4 코어 측정 기계의 부하(load average)가 9~15 로 높아 개선 전후를 가를 수 없었고, 매칭 쪽 코드는 이미 짝 단위·묶음 단위로 병렬이며 거리 계산도 벡터화되어 있어 출력을 그대로 두는 국소 수정을 시간 안에 찾지 못했다.
- 대신 `run` 이 끝날 때 단계 시간 표(큰 순)를 표준 오류로 찍도록 했다. `timing.json` 은 이미 있었다.

## 수치 표

측정 시 load average 는 9.5~14.7(4 코어 측정 기계, 다른 빌드 2개와 공유). 단계 합은 병렬 구간 때문에 벽시계보다 크다.

| 단계 | 초 | 호출 수 |
|---|---|---|
| 매칭 비율 검사 (CPU 누적) | 422.7 | 2458 |
| 매칭 RANSAC (CPU 누적) | 824.4 | 2457 |
| 매칭 (벽시계) | 316.9 | 2 |
| 특징 검출 | 116.7 | 80 |
| 밀집 깊이 | 110.9 | 4 |
| 구역 밀집 (초벌 합) | 57.4 | 2 |
| 구역 밀집 (정밀 합) | 59.8 | 2 |
| 트랙 | 8.8 | 4 |
| 융합 | 5.6 | 4 |
| 정밀 BA | 4.4 | 2 |
| 나머지(회전·위치 평균, 정렬, 쓰기 등) | 합 1 미만 | |

전체 벽시계 524.0 초 (`timing.json` 523.8). 개선 후 값은 없음(개선 미적용).

검증: 등록 240/240(초벌·정밀), 정밀 재투영 0.326 px(초벌 0.667), 스냅샷 3단계 점 37263 → 43651, final 62275, 7/7 통과.

## 방법

- `skylens-stream synth <폴더>` 기본 장면, 이어서 `run <장면> <출력> --stride 1 --span 48 --ovl 2`, `verify <출력>`.
- 최대 상주 메모리는 `/usr/bin/time` 이 없어 자식 프로세스의 `getrusage` 로 읽었다.
- 단계 시간은 `crate::timing` 누적(`timing.json`).

## 남은 문제

- 부하가 낮을 때 한 번 더 재서 단계 비율을 확인해야 한다. 이번 값은 부하 때문에 절대값이 부풀어 있다.
- 매칭 RANSAC(5점 가설 500회 × 짝 2457개)이 CPU 누적 최대다. 가설마다 Sampson 잔차를 행렬·벡터 연산으로 다시 계산하는 부분(`count_at_least`)과 표본 벡터 할당이 후보이나, 부동소수 합 순서가 바뀌면 정상 집합이 달라질 수 있어 출력 동일성 검증이 먼저 필요하다.
- 특징 검출 117 초는 위치 단위로 차례로 읽는 구조라 읽기와 검출을 겹치면 줄 여지가 있다(pipeline.rs 쪽 변경이라 보류).
