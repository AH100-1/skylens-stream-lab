# dense-regress-cause — feat/dense-accuracy 병합 뒤 단구역 점 95% 0.932 → 1.214 m 의 원인

## 결론
원인은 main 의 #67(`6a8bb90`)에 들어 있는 **작은 사진 확대 검출의 기본 동작**이다. 긴 변이 800 px 미만인 사진(이 시험은 320×180)에서
원래 검출 수가 `max_features` 의 절반에 못 미치면 2배 양선형 확대 영상에서 모자란 만큼 특징을 더한다
(`DetectorConfig::upscale_below = 800`, `--upscale-fill` 은 "항상 상한까지"를 켜는 옵션일 뿐, 모자랄 때 채우는 부분은 기본으로 켜져 있다).
같은 병합 트리에서 `upscale_below` 기본값만 0 으로 바꾸면 병합 전 수치(95% 0.932, 10302점, 중심 0.312/0.851)가 소수점 셋째 자리까지 그대로 돌아온다.
#64 도우미 사진(`4825669`)은 이 시험에 영향이 없다(`6a8bb90` 과 수치 동일). #81·#83 의 트랙 변경은 작은 보정만 한다(점 −16, 95% −0.006, 중심 중앙 −0.010).
현재 main `a1d2ad5` 를 `4f09688` 에 병합해도 같은 수치다.
점 오차가 전반적으로 커지고(중앙 0.336→0.392) 중심 오차는 오히려 줄었으므로, 포즈가 나빠진 것이 아니라 더해진 확대 특징이 만든 점이 표면에서 더 떨어져 있다.
추천: 즉시 고칠 품질 손실로 보지 않고 시험 상한을 새 실측으로 다시 잡되, 확대 특징의 점 품질(응답 하한·삼각측량 조건)을 따로 살핀다.

## 방법
- 4 코어 측정 기계, 다른 무거운 시험이 동시에 돌았다. 시험 한 번에 3분 안팎.
- `9ca267b` 에서 분리한 임시 작업 트리에 main 쪽 제1부모 커밋을 차례로 병합(로컬 전용)했다. 가장 오래된 #67 쪽부터 확인하려고 `4825669`(#64, #67 포함) 한 번,
  `6a8bb90`(#67 만) 한 번 돌렸다. 둘의 수치가 같아 #64 는 제외되고 원인이 #67 로 좁혀졌다.
- #67 의 기본 켜짐 변경은 `--upscale-fill`, `--pair-vote` 둘 다 기본 끔이라 코드만 보면 영향이 없어 보이나, `features.rs` 의 `upscale_below: 800` 은 기본 켜짐이다.
  이 시험 사진은 320×180 이고 `--max-features 800` 이라 원래 검출이 400 미만이면 채움이 일어난다. 그 값을 0 으로 바꿔 돌려 원인을 확정했다.
- 이분 탐색 대신 첫 시험에서 바로 #64/#67 구간으로 좁혀졌고 #79~#88 은 따로 병합하지 않았다. #81·#83 의 작은 보정은 `6a8bb90` 트리와 `4f09688` 의 차이로만 본다(개별 기여 분리 안 함).
- 병합 후 `a1d2ad5` 시험은 `4f09688` 에 병합해서 같은 시험을 돌렸다.

## 남은 문제
- 확대로 더해진 특징이 점 품질을 떨어뜨리는지, 단순히 더 어려운 영역(질감 약한 곳)에 점이 더 생긴 것인지 구분하지 못했다. 포즈가 바뀌어 "예전 점 부분집합" 의 오차를 따로 뽑을 수 없었다.
  1 m 초과 점이 402→1119 (+717)로 늘고 점은 +1158 늘었는데, 추가 점의 오차를 직접 보려면 점별 출처 표식이 필요하다.
- 중심 오차는 개선(0.312→0.266, 0.851→0.687)이라 포즈는 좋아졌다. 점 중앙이 0.336→0.392 로 커진 이유(확대 특징의 위치 정밀도 또는 깊이 일치 조건)는 미확인.
- 시험 상한(95% < 1.12)은 새 실측으로 바꿔야 통과한다. 제안: 실측 1.214 의 ×1.2 인 1.46 근처, 점 수 기준은 11444 로 다시 잡는다.
  다만 상한을 올리는 것은 품질 저하를 받아들이는 일이므로, 확대 채움을 켠 채 95% 를 0.93 대로 되돌릴 수 있는지(응답 하한, 확대 특징 점 제외 조건) 먼저 한 번 시험해 볼 만하다.
- F-408 질문(도우미 사진이 영향을 주었는가)에 대한 답: 이 시험에서는 영향 없음.

## 재고정 결과 (제품 브랜치 머리 기준)

### 결론
- 확대 채움을 켠 채 95% 를 되돌리는 시험은 실패했다. 확대 특징에 원래 검출 응답 중앙값 이상의 하한을 두자 단구역 95% 가 1.214 → 1.320 m, 중심 오차 중앙 0.256 → 0.281 m, 최대 0.713 → 0.740 m 로 모두 나빠졌다(점 11010). 되돌렸고 채택하지 않았다.
- 따라서 기본값은 그대로 두고 시험 상한과 주석을 현재 출력으로 다시 고정했다. 단구역 95% 상한 1.46 m(실측 1.214 의 1.2 배), 2구역 95% 상한 0.64 m(실측 0.527 의 1.21 배). 원인은 작은 사진 확대 채움 기본값(main #67)이다.
- 시험 번호 F-416·F-417·F-408-dense 해당 항목(통과 기준, README 표, 주석 불일치)은 모두 출력과 일치한다. 체인 마지막 브랜치(`feat/dense-speckle-guard`)에서 수치가 앞 브랜치와 같아 따로 다시 고정할 것이 없었다.

### 방법
- 4 코어 측정 기계에서 시험을 한 번에 하나씩 돌렸다(`--release`, 빌드 작업 2개).
- 응답 하한 시도: `detect_and_describe` 에서 확대 쪽 특징을 더할 때 원래 특징 응답의 중앙값 미만은 건너뛰게 했다. 단구역 시험 한 번만 돌렸다.
- `pipeline_e2e` 3개 모두 통과. `pipeline` 시험 7개 통과(단구역 BA 갱신 뒤 재투영 0.187 px 포함, 이 시험은 별도 합성 구성).

### 남은 문제
- 확대 특징 점이 왜 95% 를 키우는지는 여전히 점별 출처 표식이 없어 가르지 못했다. 응답 하한 외에 확대 특징끼리 근접 제거, 깊이 일치 조건 강화는 시험하지 않았다.
- 95% 상한을 올린 것은 품질 저하를 받아들인 것이다. 확대 채움을 포즈 단계에만 쓰고 점 생성에는 원래 특징만 쓰는 방법이 다음 후보.
