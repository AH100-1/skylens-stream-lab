# 카메라 쌍 회전 투표를 기본으로 켜도 되는가

## 결론

- **기본 켬으로 해도 손해는 관측되지 않았다.** 81장(stride 3) 장면 세 경우(480x270 기본, 960x540 기본, 480x270 확대 채움 + 특징 3000)에서 투표 켬은 끔보다 등록 수·verify 통과 수·정밀 재투영이 같거나 나았고, 실행 시간 차이는 측정 오차 안(최대 +4%)이다. 이득은 480x270 + 확대 채움 + 3000 에서만 드러난다: 54/81(6/7) → 81/81(7/7), 틀린 교차 카메라 간선 4개를 뺀다.
- 판정은 "켬 가능, 단 합성 장면 한 종류에서의 근거". 시드를 바꾼 장면은 못 만들었다(`synth` 에 시드 옵션이 없다). 이전 중간 기록의 120장(stride 2) 결과와도 모순이 없다.
- 현재 코드에서 실제 기본값은 다음과 같다. `PipelineConfig::pair_vote` 는 **거짓**이고 `run --pair-vote` 가 켠다(끄는 옵션은 없고 플래그를 빼는 것이 끔). 이 플래그는 초벌 회전 평균 전과 정밀 BA 시작점의 투표만 제어한다. `SparseConfig::pair_vote`(#68)는 기본 참이라 희소 단계의 투표는 플래그와 무관하게 이미 켜져 있다. 따라서 이 표의 "끔"은 "희소 단계 투표만 켜진 상태", "켬"은 거기에 파이프라인 투표를 더한 상태다. 희소 단계 투표까지 끈 비교는 제품 코드를 바꿔야 해서 하지 않았다.
- 기본 켬으로 바꾸려면 `PipelineConfig::pair_vote` 기본값을 참으로 하고 끄는 옵션(`--no-pair-vote`)을 두면 된다. 이 묶음에서는 제품 코드를 바꾸지 않았다.

## 수치 표

합성 장면 3 카메라 x 80 위치, `run --stride 3 --span 48 --ovl 2 --dense-width 96 --hfov 65 --ba-iters 15`(81장, 구역 1개). 4 코어 측정 기계, `cargo -j 2` 로 만든 릴리스 빌드, 측정 중 다른 부하는 없었다. 등록은 초벌/정밀 모두 같았다. 투표 열은 환경 변수 `SKYLENS_VOTE_STATS` 로 얻은 "뺀 간선 / 교차 카메라 간선, skipped_pairs".

| 해상도 | 설정 | 투표 | 등록 | verify | 정밀 재투영 | 뺀 간선 / 교차 간선 | skipped_pairs | 시간 |
|---|---|---|---|---|---|---|---|---|
| 480x270 | 기본 | 끔 | 54/81 | 6/7 | 0.243 px | - | - | 49.5 s |
| 480x270 | 기본 | 켬 | 54/81 | 6/7 | 0.243 px | 0 / 5 | 0 | 48.8 s |
| 960x540 | 기본 | 끔 | 81/81 | 7/7 | 0.256 px | - | - | 76.4 s |
| 960x540 | 기본 | 켬 | 81/81 | 7/7 | 0.256 px | 0 / 11 | 0 | 77.3 s |
| 480x270 | 확대 채움 + 특징 3000 | 끔 | 54/81 | 6/7 | 0.190 px | - | - | 136.7 s |
| 480x270 | 확대 채움 + 특징 3000 | 켬 | **81/81** | **7/7** | 0.198 px | 4 / 14 | 0 | 141.9 s |

- 480x270 기본에서 실패하는 항목은 `registered` 하나이고 세 번째 카메라가 0장 등록된다(끔·켬 동일). 투표만으로는 이 경우를 못 고친다(교차 간선이 5개뿐이고 모두 맞다).
- 확대 채움 조합에서 정밀 재투영은 0.190 → 0.198 px 로 조금 올랐지만 등록이 54 → 81 로 늘어난 결과이고 기준 0.7 px 안이다. 초벌 재투영은 1.403 → 0.774 px 로 줄었다.
- 시간은 켬이 계산을 조금 더 하는 정도로, 이 측정 기계에서 반복 측정은 하지 않아 4% 안팎 차이는 의미를 두지 않는다.

## 방법

- 제품 feat/vote-tests(e29110c 에서 문서 주석 한 줄만 고친 78482b9)의 릴리스 빌드로 같은 합성 장면에 끔(플래그 없음)과 `--pair-vote` 를 차례로 돌리고 `verify` 로 판정했다. 장면은 `synth <폴더> 480 270`, `synth <폴더> 960 540` 으로 각 한 번 만들었다.
- 시험: `cargo test --release -p skylens-core --lib vote` 3 개 통과, fmt·clippy(`--all-targets -D warnings`) 통과. 전체 시험 묶음은 돌리지 않았다.

## 남은 문제

- 시드가 다른 장면, 구역이 2개 이상인 장면에서의 비교.
- 희소 단계 투표(`SparseConfig::pair_vote`)만 끈 비교. 지금 CLI 로는 끌 수 없다.
- 960x540 에서 이전 기록은 특징 3000 에서 틀린 간선 1개를 뺐으나 이번 기본 설정에서는 0개였다. 특징 상한에 따라 다르므로 3000 으로 960x540 을 다시 볼 것.
- 시간 비교는 반복 측정이 아니다.
- 이전 중간 기록의 `--no-pair-vote` 옵션과 README 갱신은 아직 제품에 들어가 있지 않다.
