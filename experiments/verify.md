# verify: 출력 폴더 검증 명령

## 결론
- `skylens-stream verify <폴더>` 가 SPEC §4 일곱 항목을 판정하고 표(항목·PASS/FAIL/판정 불가·측정값·기준)를 찍는다. 종료 코드: FAIL 이 하나라도 있으면 1, FAIL 없이 판정 불가가 있으면 2, 일곱 항목 모두 PASS 면 0.
- SPEC §2 출력만으로 판정할 수 있는 항목과 없는 항목을 나눴다. 등록 사진 수·구역 사진 수·정밀 재투영 오차(항목 1~3)는 SPEC §2 의 어느 파일에도 값이 없다(파일 이름 `pos{lo}-{hi}` 로 위치 수는 알지만 사진 수는 모름). `report.json` 이 없으면 세 항목은 FAIL 이 아니라 "판정 불가" 로 표시하고, 있으면 그 값으로 판정한다. 형식이 깨진 `report.json` 은 FAIL, 출력 폴더 자체가 없으면 일곱 항목 모두 FAIL. 초벌 정렬·초벌↔정밀·정밀 겹침·스냅샷(항목 4~7)은 SPEC §2 출력만으로 측정값 판정.
- 최근접 탐색을 경계 상자 k-d 트리로 바꾸고 상한을 판정 기준 3 m 의 2배(6 m)로 낮췄다. 초벌이 정밀에서 30 m 떠 있는 구역 2개 × 9만 점 폴더가 0.97 s 에 끝나고 종료 코드 1(이전 격자 껍질 탐색은 질의 2만 개에 57.7 s, 9만 점 폴더는 400 s 안에 끝나지 않음).
- 기대 파일 목록을 만든다: 구역 집합 = report `regions` ∪ preview 구역 ∪ refined 구역 ∪ {0..마지막 정수 step}. 구역마다 preview·refined PLY, 정수 step 1..=구역 수, manifest 단계마다 스냅샷 PLY 가 있어야 한다. 빠지면 해당 항목 FAIL 과 빠진 이름 표시.
- manifest `step` 은 1 이상 정수, 최종만 `"final"`. 문자열 `"01"` 등은 형식 오류로 snapshots FAIL (SPEC §2 에 형 한 줄 추가 제안: "`step`: 정수 1..N, 최종은 문자열 `final`").
- 스케일 기준은 구역끼리의 차 max(s)/min(s) − 1 ≤ 10% 로 바꿨다(이전: 중앙값 대비 ±10% 라 0.9·1.1 이 함께 통과).
- 단조 증가는 정수 step 사이에만 적용하고 같은 수(정체)는 허용한다. final 은 refined/ PLY 점 수 합과 정확히 같아야 한다(F-157). 스트림 출력 단계는 refined/ PLY 도 구역마다 6:1 추출해 쓰고 final 도 그 추출된 구역 점군을 이어 붙이므로 비율은 1 하나뿐이다. 이전의 "e = 1..=64 중 하나와 맞으면 통과" 는 refined 861점 2개에서 final 288(다시 6:1 추출)도 통과시켰다.
- 초벌 정렬 항목은 manifest `align[].region` 집합이 기대 구역 집합과 같아야 통과한다(F-156). 빠진 구역("정렬 기록 없는 구역 [1]"), 출력에 없는 구역의 기록, 같은 구역 중복 기록은 FAIL. SPEC §3.7 이 구역 0 도 "자기 구역" 사진으로 정렬한다고 적고 있으므로 구역 0 도 기록이 있어야 한다고 해석했다. 시험 fixture 의 정렬 기록은 구역 수(2)에 맞췄다.
- report.json 이 없을 때(F-089) 항목 1~3 은 계속 "판정 불가"(종료 코드 최선 2). SPEC §2 출력에서 더 읽을 수 있는 것은 구역 파일 이름 `pos{lo}-{hi}` 의 위치 수뿐이라(hi 미포함, SPEC §3.5 의 반열린 구간), 구역 사진 수 항목의 측정값 칸에 "파일 이름의 위치 수 [0:14 1:16], 사진 수는 출력에 없음" 을 참고로 적는다. 초벌·정밀 이름의 위치 범위가 다르면 그 구역도 적는다. 등록 사진 수·재투영 오차는 manifest·PLY 어디에도 단서가 없다.

## 방법
- 등록: `registered.preview == total` 이고 `registered.refined == total`.
- 구역 사진 수: `regions[].images == 3 × regions[].positions`.
- 재투영: `reprojection_px.refined ≤ 0.7`.
- 초벌 정렬: `align[].region`(음이 아닌 정수) 집합 = 기대 구역 집합, 중복 없음. manifest `align` 전부에서 `pairs ≥ 1000`, `fit_median_m < 6`, max(scale)/min(scale) − 1 ≤ 0.10 (부동소수 여유 1e-9, 0 이하 스케일은 실패).
- 초벌↔정밀: 같은 구역 번호 k 의 `preview_kk_*.ply` 와 `refined_kk_*.ply`. 초벌 점마다
  - 3D 최근접 거리의 중앙 < 3 m. 6 m 너머는 찾지 않고 6 m 로 두며 표에는 "> 6.000 m",
  - 수평 2 m 안의 수평 최근접 정밀 점과 짝을 지은 |Δz| 의 중앙 < 2 m (짝 없는 점은 뺌).
  - 전체 점군 중앙값끼리는 비교하지 않는다. 구역마다 계산해 최댓값으로 판정.
- 최근접 자료 구조: 잎 16 점 k-d 트리, 노드마다 경계 상자. 상자까지 거리가 현재 최선(처음엔 상한)보다 크면 통째로 건너뛰므로 빈 공간 질의는 노드 몇 개로 끝난다. 2D(수평)는 z 를 무시.
- 유한하지 않거나 |좌표| > 1e7 m 인 점은 뺀다 (x = 1e30 점이 섞여도 디버그 빌드에서 넘침 없음).
- 이웃 정밀 겹침: 번호 순 이웃 구역 쌍마다 수평 1 m 짝 |Δz| 중앙 < 0.3 m. 정밀 0개 FAIL, 기대 구역 중 정밀이 빠지면 FAIL, 구역 1개면 "해당 없음"(PASS).
- 스냅샷: final 점 수 = Σ refined/ PLY 점 수, 정수 step 사이 점 수 감소 FAIL, step ≥ 2 에서 `preview_new_area > 0`, final 정확히 1개, manifest 단계마다 파일 존재·NaN 없음·파일 점 수 = manifest, manifest 에 없는 `step_*.ply` 도 문제로 표시.
- 점이 20만 개를 넘으면 질의 점을 일정 간격으로 추린다.
- CLI 연결은 `["verify", dir] => verify::run_cli(dir)` 한 줄, 표 출력·종료 코드는 `verify::run_cli`.

- 판정 불가: `report.json` 이 없고 출력 폴더는 있을 때 항목 1~3 의 `decided = false`. 표에는 "판정 불가", 요약 줄 아래 "판정 불가: n개 (SPEC §2 출력에 없는 값)". `Report::exit_code()` 가 0/1/2 를 정한다. `all_pass()` 는 일곱 항목 모두 판정·통과일 때만 참.

### report.json 형식 (SPEC §2 추가 제안)
```json
{"registered": {"total": 240, "preview": 240, "refined": 240},
 "reprojection_px": {"preview": 4.5, "refined": 0.59},
 "regions": [{"region": 0, "positions": 14, "images": 42}]}
```
SPEC §2 출력 목록에 "`report.json`: 등록 사진 수(전체·초벌·정밀), 재투영 RMS(px), 구역별 위치 수·사진 수" 한 줄과 위 형식을 올리고, 스트림 출력 단계가 이 파일을 쓰도록 맞춰야 한다. 그 전까지 SPEC §2 대로만 만든 폴더는 항목 1~3 이 "판정 불가" 로 남고 종료 코드는 최선이 2 다.

## 남은 문제
- **결정 필요 (F-089)**: 항목 1~3(등록 사진 수·구역 사진 수·정밀 재투영)은 SPEC §2 출력 어디에도 값이 없다. 이번에 확인한 바로 manifest·PLY 에서 얻을 수 있는 것은 파일 이름의 구역 위치 수뿐이고 사진 수·등록 수·재투영 오차는 없다. 선택지:
  (가) SPEC §2 에 `report.json`(위 형식) 을 올리고 `stream::write_outputs` 가 쓰게 한다 → 1~3 측정값 판정, 실제 출력 종료 0 가능.
  (나) 같은 값을 `snapshots/manifest.json` 의 새 키(`registered`, `reprojection_px`, `regions`)로 넣는다 → 출력 파일 수는 그대로, verify 는 읽는 위치만 바꾸면 된다.
  (다) 1~3 을 출력 검증 대상에서 빼고 파이프라인 실행 기록(run 단계 로그)에서 판정한다 → verify 는 4/4 로 종료 0.
  SPEC 은 고치지 않았고 verify 는 지금 동작(없으면 판정 불가, 종료 2)을 유지한다. 셋 중 무엇으로 할지 정해야 한다.
- report.json 을 쓰는 쪽(스트림 출력)이 아직 없다(main 병합 뒤 재확인, `write_outputs` 는 PLY·manifest 만 씀). 그 전까지 실제 출력은 최선이 종료 코드 2.
- main 병합 뒤 다시 본 결과 현재 main 의 스트림 manifest 는 step 을 문자열 `"01"` 로 쓴다. 스트림 쪽이 정수로 고치기 전에는 실제 출력의 snapshots 항목이 형식 오류로 FAIL 한다. 스트림 수정 뒤 `write_outputs` 결과를 바로 verify 하는 시험을 붙여야 한다.
- 구역 1개 출력의 겹침 "해당 없음" 은 PASS 로 센다. 표에서 따로 표시할지 정해야 한다.
- 겹침 차를 수평 1 m 짝 높이 차로 재는 방식은 경사면이 많은 실제 데이터에서 3D 최근접과 비교가 필요하다.
