# pair-schedule — 짝 생성에 2의 거듭제곱 간격 추가 (FEEDBACK F-013)

## 결론
- `candidate_pairs` 가 SPEC §3.2 "같은 카메라 시간 이웃: 위치 차 1..5 와 2의 거듭제곱 간격"을 구현한다.
  같은 카메라는 `d ≤ temporal` 또는 (`d` 가 2의 거듭제곱이고 `d ≤ pow2_max`), 다른 카메라는 `d ≤ cross`.
- SPEC 기본값을 상수 `PAIR_TEMPORAL = 5`, `PAIR_CROSS = 4`, `PAIR_POW2_MAX = usize::MAX`(제한 없음)로 두었다.
- 위치 80 × 카메라 3 에서 같은 카메라 위치 차 집합 = {1,2,3,4,5,8,16,32,64}, 짝 수 3855 = 손 계산과 일치(테스트).

## 수치 (위치 80 × 카메라 3, SPEC 기본값)

| 구분 | 이전 | 이후 | 손 계산 |
|---|---|---|---|
| 같은 카메라 짝(3대 합) | 1155 | 1755 | 3 × [(79+78+77+76+75) + (72+64+48+16)] = 3 × 585 |
| 다른 카메라 짝 | 2100 | 2100 | 3 × [80 + 2(79+78+77+76)] = 3 × 700 |
| 합계 | 3255 | **3855** | |
| 같은 카메라 d=8 짝 | 0 | 216 | 3 × 72 |
| 상한 `pow2_max = 16` | — | 3663 | 3855 − 3 × (48+16) |

## 방법
- 조건만 바꿨다: `d >= 1 && (d <= temporal || (d.is_power_of_two() && d <= pow2_max))`. `pow2_max = 0` 이면 이전 동작.
- 테스트 `candidate_pairs_power_of_two_gaps`: 위치 차 집합 `assert_eq!`, 다른 카메라 |d| ≤ 4 단언, 짝 수 3855, 상한 16 에서 3663.
  기존 `candidate_pairs_counts` 는 `pow2_max = 0` 으로 이전 값(135) 유지.
- 제품 README 한국어·English 절에 사용 예를 함께 추가.

## 남은 문제
- 짝 수가 18% 늘어 F-014(매칭 속도) 부담이 커진다. F-014 에서 함께 측정.
- 거듭제곱 간격 짝은 겹침이 작을 수 있다(먼 위치). 기하 검증 실패율은 T07 이후 실제 파이프라인에서 확인.
